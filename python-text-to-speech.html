Lesson 1 — What Is Text to Speech, and Why Use Python?

Text-to-speech (TTS) is the process of converting written text into spoken audio. It's the same technology behind screen readers, voice assistants, GPS navigation, audiobook generators, and accessibility features on every major platform. In Python, TTS is available through both offline libraries (which run on your machine) and cloud APIs (which produce more natural-sounding voices).

Key idea: A TTS system takes a string, analyses it (pronunciation, intonation, pauses), synthesises a waveform, and outputs audio — either through speakers or saved as a file. Python gives you several ways to do this, from 5-line scripts to production cloud services.

🧰 The Tools You'll Use in This Course

🔊

pyttsx3

Offline, free, cross-platform. Uses your OS's built-in TTS engine (SAPI5 on Windows, NSSpeechSynthesizer on macOS, espeak on Linux). Fast and private.

🌐

gTTS

Online, free, needs internet. Uses Google Translate's TTS endpoint. More natural voice, works for many languages, produces MP3 files.

☁️

Amazon Polly

Cloud API, pay-per-character. Neural voices that sound almost human. Production-grade, used in apps with millions of users.

🎧

pydub / playsound

Play or manipulate generated audio. Convert MP3 to WAV, change speed, combine segments.

⚖️ Offline vs Online TTS — Which to Use?

Use offline (pyttsx3) when: you need it to work without internet, you care about privacy (text never leaves your machine), you need zero latency, or you're building a desktop app.

Use online (gTTS, Polly) when: audio quality matters (natural-sounding voices), you need many languages, you want to save high-quality MP3s, or you're building a cloud service.

🧪 Runnable Example — Verify Your TTS Setup

This first example verifies that pyttsx3 can find a voice on your system. It doesn't play audio yet — just lists the voices available. Run this locally.

python 
import pyttsx3

engine = pyttsx3.init()
voices = engine.getProperty("voices")

print(f"Found {len(voices)} voice(s):")
for i, voice in enumerate(voices):
    print(f"  [{i}] {voice.name} ({voice.id})")
Line-by-line explanation
  • 1
    import pyttsx3 — Loads the library. Install it first with pip install pyttsx3. On Linux you also need sudo apt install espeak espeak-data libespeak1 libespeak-dev.
  • 3
    engine = pyttsx3.init() — Creates and initialises the TTS engine. Behind the scenes, this detects your OS and loads the appropriate speech backend: SAPI5 on Windows, NSSpeechSynthesizer on macOS, espeak on Linux. This is the object you use for all speech operations.
  • 4
    voices = engine.getProperty("voices") — Asks the engine for a list of available voices. Each voice is a Voice object with attributes like .id (a unique string you'll use to select that voice later), .name (human-readable name), .languages (list of language codes), and .gender.
  • 6
    print(f"Found {len(voices)} voice(s):") — Reports how many voices are installed. Most Windows/macOS systems come with at least 2–4 by default. Linux with just espeak ships with several variants.
  • 7
    for i, voice in enumerate(voices): — Loops through each voice, using enumerate to get both the index i and the voice object. The index is useful for selecting a voice later by number.
  • 8
    print(f" [{i}] {voice.name} ({voice.id})") — Prints the index, name, and ID of each voice. You'll use either the index or the ID to select a voice in Lesson 3. The ID often looks like "HKEY_LOCAL_MACHINE\\SOFTWARE\\Microsoft\\Speech\\Voices\\Tokens\\TTS_MS_EN-US_DAVID_11.0" on Windows — long but unique.
Run Locally Only — pyttsx3 requires access to your operating system's speech engine. It cannot run inside the browser-based Python runner. Install it locally with pip install pyttsx3 and run with python file.py.

Lesson 2 — Meet pyttsx3: Your First Spoken Sentence

Now that you know pyttsx3 exists, let's make it speak. This lesson covers the three core methods — say(), runAndWait(), and stop() — and explains why you need both say and runAndWait.

🔊 Speak a Single Sentence

python 
import pyttsx3

engine = pyttsx3.init()

engine.say("Hello from Python. This is your first spoken sentence.")
engine.runAndWait()

engine.say("Notice how we call say first, then runAndWait.")
engine.runAndWait()

print("All speech finished.")
Line-by-line explanation
  • 1
    import pyttsx3 — Same import as before.
  • 3
    engine = pyttsx3.init() — Initialises the engine. Do this once per program — not once per sentence. Reusing the engine is faster and avoids resource leaks.
  • 5
    engine.say("...") — Queues the text to be spoken. Important: this doesn't actually start speaking — it adds the text to an internal queue. Think of it like pressing "add to playlist" rather than "play". You can queue multiple say() calls and they'll all play in order.
  • 6
    engine.runAndWait() — Starts the engine and blocks until the queue is empty. This is what actually makes the audio come out of your speakers. If you forget this call, you'll queue up text but hear nothing — one of the most common beginner mistakes.
  • 8–9
    The second say + runAndWait pair. Same pattern — queue then execute. You could also queue both say calls and then call runAndWait once at the end; they'd play in sequence. The one-at-a-time pattern is clearer for learning.
  • 11
    print("All speech finished.") — Reaches this line only after both runAndWait() calls have returned, meaning both sentences have finished playing. Without a block like runAndWait, the script would exit immediately and you'd hear nothing (or audio would cut off mid-sentence).
💡 Why say then runAndWait? The split exists because pyttsx3 needs to support queuing multiple utterances and other operations. say() enqueues; runAndWait() starts the engine. Without the split, you couldn't queue several sentences and then have them play as one uninterrupted stream.

⏹️ Stopping Speech Mid-Sentence

If you're reading a long text and want to interrupt it, call engine.stop(). Here's a simple pattern where the user can press Enter to stop the reading:

python 
import pyttsx3
import threading

engine = pyttsx3.init()

def speak():
    engine.say("This is a long speech. Press Enter in the terminal to stop it.")
    engine.say("You can also call stop at any time to interrupt.")
    engine.runAndWait()

thread = threading.Thread(target=speak)
thread.start()

input("Press Enter to stop the speech...")
engine.stop()
thread.join()
print("Speech stopped.")
Line-by-line explanation
  • 1
    import pyttsx3 — The TTS library.
  • 2
    import threading — Standard library. We need it because runAndWait() blocks the calling thread — we can't wait for user input on the same thread.
  • 4
    engine = pyttsx3.init() — Initialise once.
  • 6
    def speak(): — A function that queues two sentences and starts speaking. Runs in a separate thread so the main thread can wait for input simultaneously.
  • 7–8
    Queue two sentences with say(). They'll play one after the other.
  • 9
    engine.runAndWait() — Starts speaking. Blocks this thread until both sentences finish — or until engine.stop() is called from another thread.
  • 11
    thread = threading.Thread(target=speak) — Creates a thread object that will run the speak function when started. Nothing has run yet.
  • 12
    thread.start() — Starts the thread. speak() begins running in parallel with the main thread. Speech starts immediately.
  • 14
    input("Press Enter to stop...") — Blocks the main thread until the user presses Enter. Meanwhile, the speech thread is playing audio.
  • 15
    engine.stop() — Called when the user presses Enter. Immediately halts the engine's current utterance and clears the queue. Speech stops.
  • 16
    thread.join() — Waits for the speech thread to finish. Since engine.stop() caused runAndWait to return, the thread exits quickly — this ensures we don't print the final line before the thread is truly done.
  • 17
    print("Speech stopped.") — Confirms it's done.
⚠️ On some systems, calling engine.stop() from a different thread can occasionally cause the engine to become unresponsive for the next utterance. If you plan to use the same engine after stopping, test carefully, or re-initialise with pyttsx3.init() after stopping.

Lesson 3 — Controlling Rate, Volume & Voice

The default voice and speed are often too fast or too robotic. This lesson shows how to slow down, speed up, change volume, and pick a specific voice. These controls transform pyttsx3 from "speaks text" into "speaks text well".

⚙️ The Three Properties You Can Control

  • rate — Words per minute. Default is usually ~200. Lower = slower.
  • volume — Float between 0.0 (silent) and 1.0 (full).
  • voice — A specific voice object from engine.getProperty("voices").

You set these with engine.setProperty(name, value) and read them with engine.getProperty(name).

🧪 Runnable Example — Slow, Loud, Custom Voice

python 
import pyttsx3

engine = pyttsx3.init()

current_rate   = engine.getProperty("rate")
current_volume = engine.getProperty("volume")
print(f"Default rate: {current_rate} wpm")
print(f"Default volume: {current_volume}")

engine.setProperty("rate", 150)
engine.setProperty("volume", 0.9)

voices = engine.getProperty("voices")
if len(voices) > 1:
    engine.setProperty("voice", voices[1].id)

engine.say("Now I am speaking slower, and my volume is turned up.")
engine.runAndWait()
Line-by-line explanation
  • 1
    Import pyttsx3.
  • 3
    engine = pyttsx3.init() — Initialise.
  • 5–6
    current_rate = engine.getProperty("rate") and current_volume = engine.getProperty("volume") — Reads the current settings so you know what you're starting from. Useful for debugging — sometimes a system's default rate is wildly different from what you expect.
  • 7–8
    Print the current defaults. On most systems you'll see something like Default rate: 200 wpm and Default volume: 1.0. Rates vary by OS — Windows SAPI5 typically defaults to 200, espeak often defaults to 175.
  • 10
    engine.setProperty("rate", 150) — Sets the speaking rate to 150 words per minute. Slower than the default 200. Try values like 100 (very slow), 150 (comfortable), 200 (normal), 300 (fast). Note: some engines interpret rate as a percentage rather than WPM — espeak, for example, uses a 80–450 range. Test empirically on your platform.
  • 11
    engine.setProperty("volume", 0.9) — Sets volume to 90% of max. Range is 0.0 to 1.0. Values outside this range are usually clamped — but don't rely on that; keep values in [0.0, 1.0].
  • 13
    voices = engine.getProperty("voices") — Retrieves the list of available voices.
  • 14–15
    if len(voices) > 1: engine.setProperty("voice", voices[1].id) — If at least two voices exist, select the second one. We pass voices[1].id, not voices[1] — the engine expects the voice ID string, not the Voice object. This is a very common mistake for beginners.
  • 17
    engine.say("Now I am speaking slower...") — Queue the text. It will be spoken with the rate, volume, and voice we just set. Note that properties are read when the engine actually plays the audio, not when say() is called — so you can change properties between say calls if you want different utterances to have different settings.
  • 18
    engine.runAndWait() — Plays it.
💡 Discovering what voices exist: The voice list differs wildly between platforms. Windows usually has "David" and "Zira" (male/female English). macOS has "Alex", "Samantha", "Victoria", etc. Linux with espeak has a dozen variants (en, en-us, en-gb, etc.). Print the voices to see what's available before guessing.

🗣️ Listing Voices with Names and Languages

For a more useful voice picker, inspect each voice's attributes:

python 
import pyttsx3

engine = pyttsx3.init()
voices = engine.getProperty("voices")

for i, v in enumerate(voices):
    langs = ", ".join(v.languages) if v.languages else "unknown"
    gender = getattr(v, "gender", "unknown") or "unknown"
    print(f"[{i}] {v.name}")
    print(f"     ID: {v.id}")
    print(f"     Languages: {langs}")
    print(f"     Gender: {gender}\n")
  • 1–2
    Import and initialise.
  • 3
    Get the voices list.
  • 5
    for i, v in enumerate(voices): — Loop with index and voice object.
  • 6
    langs = ", ".join(v.languages) if v.languages else "unknown" — v.languages is a list like ["en-US"]. Join into a comma-separated string. If the list is empty or missing, show "unknown". The ternary prevents an AttributeError if a voice doesn't expose languages.
  • 7
    gender = getattr(v, "gender", "unknown") or "unknown" — Two layers of safety: getattr returns "unknown" if the attribute doesn't exist; the or "unknown" handles the case where the attribute exists but is None. Some voices report gender, some don't.
  • 8–11
    Print the four attributes. Two blank lines (\n\n) between voices make the output readable.
✨ Voice IDs are the only reliable selector. Voice names can be duplicated or changed between OS updates; voice IDs are stable. Always store and use the ID, even if you display the name to users.

Lesson 4 — Saving Speech to a File (pyttsx3)

Playing audio is great for demos, but real applications need to save speech to a file: to embed in a video, attach to an email, listen offline, or generate an audiobook. pyttsx3 supports this via save_to_file() — with important caveats.

💾 The save_to_file() Pattern

python 
import pyttsx3

engine = pyttsx3.init()
engine.setProperty("rate", 160)

text = "This audio is being saved to a file for later listening."
output_path = "speech.wav"

engine.save_to_file(text, output_path)
engine.runAndWait()

print(f"Saved to {output_path}")
Line-by-line explanation
  • 1
    Import pyttsx3.
  • 3
    Initialise the engine.
  • 4
    engine.setProperty("rate", 160) — Set the speaking rate. This property applies to the saved audio too — whatever properties are set at the time save_to_file runs will be baked into the file.
  • 6
    text = "..." — The text to convert to speech.
  • 7
    output_path = "speech.wav" — The output file path. Use a .wav extension, not .mp3. pyttsx3 uses each OS's native TTS engine, and those engines typically output WAV (SAPI5 outputs WAV, NSSpeechSynthesizer outputs AIFF on some macOS versions, espeak outputs WAV). Some platforms won't produce valid MP3s even if you name the file .mp3.
  • 9
    engine.save_to_file(text, output_path) — Queues a "save this text to this file" operation. Like say(), this just queues the operation — it doesn't actually write anything yet.
  • 10
    engine.runAndWait() — Executes the queued operations. This is what actually synthesises the audio and writes the file. Without this call, the file is never created.
  • 12
    print(f"Saved to {output_path}") — Confirmation. At this point the file should exist — but see the warning below.
Platform-specific gotcha: save_to_file() works reliably on Windows (SAPI5) and most macOS setups (NSSpeechSynthesizer), but espeak on Linux frequently fails silently — it prints no error, but no file is created. If you're on Linux and the file doesn't appear, try running espeak -w output.wav "test" directly from the terminal to verify espeak itself works. If it does, you may need to switch to gTTS (Lesson 5) for file output.

📼 Converting WAV to MP3 (Optional)

If you need an MP3 (smaller files, wider compatibility), the pydub library can convert — but it requires ffmpeg installed on your system:

python 
from pydub import AudioSegment

audio = AudioSegment.from_wav("speech.wav")
audio.export("speech.mp3", format="mp3")

print("Converted to speech.mp3")
  • 1
    from pydub import AudioSegment — Import the audio-processing class. Install with pip install pydub. You also need ffmpeg installed on your system (brew install ffmpeg on macOS, sudo apt install ffmpeg on Linux, or download from ffmpeg.org on Windows).
  • 3
    AudioSegment.from_wav("speech.wav") — Loads the WAV file into memory as an AudioSegment object. This object exposes dozens of audio operations (trimming, volume, fade, speed).
  • 4
    audio.export("speech.mp3", format="mp3") — Encodes and writes an MP3 file. The format="mp3" tells pydub which codec to use. Behind the scenes, pydub calls ffmpeg.
  • 6
    Confirmation print.
⚠️ If pydub raises CouldntDecodeError or FileNotFoundError, it means ffmpeg isn't installed or isn't on your PATH. Check by running ffmpeg -version in your terminal.

Lesson 5 — Google TTS with gTTS

pyttsx3 is fine for local use, but the voices are robotic and the file output is unreliable on some platforms. gTTS (Google Text-to-Speech) uses Google Translate's TTS endpoint. It's free, produces natural-sounding MP3 files, and supports many languages — but it requires an internet connection.

🌐 Generating Speech with gTTS

python 
from gtts import gTTS

text = "Hello, this is Google Text to Speech. I sound more natural than pyttsx3."

tts = gTTS(text=text, lang="en", slow=False)
tts.save("google_tts.mp3")

print("Saved to google_tts.mp3")
Line-by-line explanation
  • 1
    from gtts import gTTS — Import the class. Install first with pip install gTTS.
  • 3
    text = "..." — The text to speak. This gets sent to Google's servers — don't use it for anything confidential.
  • 5
    tts = gTTS(text=text, lang="en", slow=False) — Creates a gTTS object. Three arguments:
  • —
      text — The string to convert. Can be up to ~100 characters per request if you're calling repeatedly; for longer text, gTTS handles chunking internally, but rate limits apply.
  • —
      lang — ISO 639-1 language code. "en" for English, "es" for Spanish, "fr" for French, "ja" for Japanese, etc. Use "en-gb" for British accent, "en-au" for Australian, "en-in" for Indian English.
  • —
      slow=False — When True, gTTS speaks more slowly — useful for language learners. When False, natural pace.
  • 6
    tts.save("google_tts.mp3") — Writes the audio to an MP3 file. Unlike pyttsx3, this saves the file immediately — no runAndWait needed. gTTS handles the network call and MP3 encoding synchronously inside .save().
  • 8
    Confirmation print.
💡 Speed of gTTS: Each request usually takes 1–3 seconds because it's making an HTTP call to Google. For bulk generation of many files, consider batching or using a local TTS for speed. For infrequent, high-quality generation, gTTS is excellent.

🎧 Playing gTTS Audio Immediately

If you want to hear the audio right away (rather than just saving it), combine gTTS with a playback library. The simplest option is playsound:

python 
from gtts import gTTS
from playsound import playsound

tts = gTTS(text="Playing audio directly from memory.", lang="en")
tts.save("temp_speech.mp3")

playsound("temp_speech.mp3")

print("Playback complete.")
  • 1
    Import gTTS.
  • 2
    from playsound import playsound — Import the play function. Install with pip install playsound. Note: newer versions of playsound have compatibility issues on Python 3.10+; if you hit problems, use pip install playsound==1.2.2 to get the stable version.
  • 4–5
    Generate speech and save it to a temporary file. gTTS needs a file to write to — it can't play audio directly from memory with the playsound library.
  • 7
    playsound("temp_speech.mp3") — Plays the MP3 through your default audio device. Blocks until playback finishes — so the next line runs only after the audio completes.
  • 9
    Confirmation print — reached only after playback finishes.
✨ Alternative: pydub.playback. If playsound gives you trouble, install pydub and simpleaudio: pip install pydub simpleaudio (or pip install pydub pyaudio). Then: from pydub import AudioSegment; from pydub.playback import play; play(AudioSegment.from_mp3("temp_speech.mp3")). This is more reliable on Linux.

🌍 Multilingual Example — Speak in Three Languages

python 
from gtts import gTTS

phrases = [
    ("en", "Hello, how are you?"),
    ("es", "Hola, ¿cómo estás?"),
    ("fr", "Bonjour, comment allez-vous ?"),
]

for lang, text in phrases:
    tts = gTTS(text=text, lang=lang)
    filename = f"hello_{lang}.mp3"
    tts.save(filename)
    print(f"Saved: {filename}")
  • 3–7
    phrases = [...] — A list of tuples. Each tuple is (language_code, text). This structure makes it easy to loop over many language/text pairs.
  • 9
    for lang, text in phrases: — Tuple unpacking in the loop header. lang gets the first element of each tuple, text gets the second.
  • 10
    tts = gTTS(text=text, lang=lang) — Creates a new gTTS object per iteration, with the current language and text.
  • 11
    filename = f"hello_{lang}.mp3" — Builds a filename that includes the language code. So the outputs are hello_en.mp3, hello_es.mp3, hello_fr.mp3. Simple but effective — each language gets its own file.
  • 12
    tts.save(filename) — Saves the audio. Note that each language uses the same voice infrastructure but with a different language model — so the Spanish version will sound like native Spanish, not English-with-Spanish-words.
  • 13
    Print confirmation for each file.

Lesson 6 — Amazon Polly: Production-Grade Neural TTS

Amazon Polly is a paid cloud service that produces neural voices — audio so natural it sounds like a professional voice actor. It's the same TTS that powers many commercial products. This lesson shows how to use it in Python via the AWS SDK (boto3), and covers the free tier (5 million characters per month, 12 months free).

🔐 Setting Up AWS Credentials

Before you can call Polly, you need AWS credentials. Here's the process:

  1. Create a free AWS account at aws.amazon.com.
  2. Go to IAM → Users → Create user.
  3. Name the user (e.g. polly-user), choose "Programmatic access".
  4. Attach the AmazonPollyFullAccess policy.
  5. Save the Access Key ID and Secret Access Key.
  6. Install the SDK: pip install boto3.
  7. Set credentials either via aws configure (recommended) or environment variables.
Never hardcode AWS credentials in source files. If you commit a script with aws_access_key_id="AKIA..." to GitHub, bots will find it within minutes and rack up charges on your account. Use aws configure or environment variables instead — always.

🧪 Generating Speech with Polly

python 
import boto3

polly = boto3.client("polly", region_name="us-east-1")

text = "Welcome to Amazon Polly. This voice is neural and sounds almost human."

response = polly.synthesize_speech(
    Text=text,
    OutputFormat="mp3",
    VoiceId="Joanna",
    Engine="neural",
)

with open("polly_output.mp3", "wb") as f:
    f.write(response["AudioStream"].read())

print("Saved polly_output.mp3")
Line-by-line explanation
  • 1
    import boto3 — The AWS SDK for Python. boto3 is the current version (boto2 is legacy). Install with pip install boto3.
  • 3
    polly = boto3.client("polly", region_name="us-east-1") — Creates a client for the Polly service in the US East (N. Virginia) region. Region matters — voice availability varies by region. us-east-1 has the widest selection, including all the neural voices. Other regions have fewer voices. If you don't have credentials set up yet, this line will fail with a NoCredentialsError.
  • 5
    The text to speak. Polly handles up to 3,000 characters per call (for long text, use the async start_speech_synthesis_task API).
  • 7
    response = polly.synthesize_speech(...) — The API call. Returns a response dict with the audio stream.
  • 8
    Text=text — The string to convert. Max 3,000 characters for the synchronous API.
  • 9
    OutputFormat="mp3" — Audio format. Options: "mp3", "ogg_vorbis", "pcm". MP3 is the most universally playable.
  • 10
    VoiceId="Joanna" — The voice name. Popular neural voices: Joanna (en-US female), Matthew (en-US male), Amy (en-GB female), Olivia (en-AU female), Lucia (es-ES female), Takumi (ja-JP male). Full list at docs.aws.amazon.com/polly/latest/dg/voicelist.html.
  • 11
    Engine="neural" — Choose the neural engine. This is what gives Polly its natural sound. Alternatives: "standard" (older, cheaper, more robotic) and "long-form" (for reading long text with consistent intonation). Neural costs more per character but sounds dramatically better.
  • 14
    with open("polly_output.mp3", "wb") as f: — Opens a binary-write file. The "wb" mode is critical — audio is bytes, not text. Using "w" would corrupt the file with Unicode encoding errors.
  • 15
    f.write(response["AudioStream"].read()) — response["AudioStream"] is a StreamingBody object (a file-like object holding the audio data). .read() loads all its bytes into memory. Then f.write(...) writes those bytes to disk. If the audio is very long, this could be memory-heavy — for those cases, use shutil.copyfileobj(response["AudioStream"], f) to stream instead.
  • 17
    Confirmation.

📊 Polly Pricing (as of 2026)

Free tier: 5 million characters per month for 12 months (both neural and standard combined).

Standard engine: $4 per million characters.

Neural engine: $16 per million characters.

Long-form engine: $100 per million characters (used for audiobooks).

For perspective: the entire text of Pride and Prejudice (~700,000 characters) would cost about $11 with the neural engine. A 1,000-word blog post (~6,000 characters) costs about $0.10.

Lesson 7 — Reading from Files and URLs

Speaking a hardcoded string is fine for demos. But real applications speak content — a text file on disk, an article fetched from the web, or a paragraph extracted from a PDF. This lesson connects the TTS engines from Lessons 2–6 to text sources.

📄 Reading a Text File Aloud

python 
import pyttsx3
from pathlib import Path

engine = pyttsx3.init()
engine.setProperty("rate", 170)

file_path = Path("article.txt")

if not file_path.exists():
    print(f"File not found: {file_path}")
else:
    text = file_path.read_text(encoding="utf-8")
    print(f"Read {len(text)} characters")

    engine.say(text)
    engine.runAndWait()

    print("Finished reading.")

✂️ Splitting Long Text into Speakable Chunks

python 
import pyttsx3
import re

engine = pyttsx3.init()

def chunk_text(text, max_chars=500):
    sentences = re.split(r"(?<=[.!?])\s+", text)
    chunks = []
    current = ""
    for s in sentences:
        if len(current) + len(s) + 1 <= max_chars:
            current = (current + " " + s).strip()
        else:
            if current:
                chunks.append(current)
            current = s
    if current:
        chunks.append(current)
    return chunks

long_text = (
    "This is the first sentence. Here is another one with more content. "
    "And a third. Finally, a fourth sentence to close."
)

for i, chunk in enumerate(chunk_text(long_text, 80)):
    print(f"Chunk {i+1}: {chunk}")
    engine.say(chunk)
    engine.runAndWait()

🌐 Reading an Article from a URL

Combine requests + BeautifulSoup + TTS to speak a web article aloud. This is the pattern used by podcast generators and accessibility tools.

python 
import requests
from bs4 import BeautifulSoup
from gtts import gTTS

url = "https://en.wikipedia.org/wiki/Text-to-speech"

soup = BeautifulSoup(response.text, "html.parser")

paragraphs = soup.select("#mw-content-text p")[:5]
article_text = " ".join(p.get_text(strip=True) for p in paragraphs)

print(f"Extracted {len(article_text)} characters")

tts = gTTS(text=article_text, lang="en")
tts.save("article_audio.mp3")

print("Saved article_audio.mp3")

Lesson 8 — Building a CLI Text-to-Speech Tool

This lesson brings everything together into a single, reusable command-line tool. The goal: python tts.py input.txt -o output.mp3 -e gtts -v en — a small utility that reads any text file and speaks it, with options for engine, voice, rate, and output file.

🎯 The Design

Command-line interface: Use argparse so the tool behaves like a proper Unix utility.

Engine abstraction: One function per engine (pyttsx3, gTTS) behind a common interface, so adding Polly later is a 20-line addition.

Input flexibility: Accept a file path, a string, or stdin — so the tool works in pipelines (cat article.txt | python tts.py -).

Safe defaults: gTTS for output quality, pyttsx3 for instant playback, auto-detect from the output file extension.

🧱 Step 1 — The Argument Parser

python 
import argparse
from pathlib import Path

def build_parser():
    p = argparse.ArgumentParser(
        description="Convert text to speech from a file, string, or stdin."
    )
    p.add_argument("source", nargs="?", default="-",
                   help="File path, '-' for stdin, or a quoted string.")
    p.add_argument("-o", "--output", default=None,
                   help="Save audio to this file (.mp3 or .wav). Omit to play.")
    p.add_argument("-e", "--engine", choices=["pyttsx3", "gtts"], default="gtts",
                   help="Which TTS engine to use (default: gtts).")
    p.add_argument("-v", "--voice", default=None,
                   help="Voice ID (pyttsx3) or language code (gTTS).")
    p.add_argument("-r", "--rate", type=int, default=170,
                   help="Speech rate in words per minute (pyttsx3 only).")
    p.add_argument("--volume", type=float, default=1.0,
                   help="Volume between 0.0 and 1.0 (pyttsx3 only).")
    return p

if __name__ == "__main__":
    args = build_parser().parse_args()
    print(args)

🔧 Step 2 — Reading Input from Any Source

python 
import sys
from pathlib import Path

def read_input(source):
    if source == "-":
        if sys.stdin.isatty():
            raise SystemExit("No input. Pass a file, a quoted string, or pipe via stdin.")
        return sys.stdin.read()

    p = Path(source)
    if p.is_file():
        return p.read_text(encoding="utf-8")

    return source

⚙️ Step 3 — The Engine Functions

python 
def speak_pyttsx3(text, output=None, voice=None, rate=170, volume=1.0):
    import pyttsx3
    engine = pyttsx3.init()
    engine.setProperty("rate", rate)
    engine.setProperty("volume", volume)
    if voice:
        engine.setProperty("voice", voice)

    if output:
        engine.save_to_file(text, str(output))
    else:
        engine.say(text)
    engine.runAndWait()

def speak_gtts(text, output=None, voice="en"):
    from gtts import gTTS
    tts = gTTS(text=text, lang=voice or "en")
    if output:
        tts.save(str(output))
    else:
        import tempfile, os
        from playsound import playsound
        with tempfile.NamedTemporaryFile(suffix=".mp3", delete=False) as f:
            tmp = f.name
        try:
            tts.save(tmp)
            playsound(tmp)
        finally:
            os.unlink(tmp)

  • 3–5
    Initialise and set properties. Properties are applied regardless of play-vs-save, since they affect the saved file too.
  • 6–7

  • 9–10

  • 11–12

  • 13
    engine.runAndWait() — Executes whichever operation we queued.
  • 15
    def speak_gtts(text, output=None, voice="en"): — gTTS uses voice as a language code, so the parameter is reused with a different meaning.
  • 16–17
    gTTS(text=text, lang=voice or "en") — If voice is empty/None, default to English.
  • 18–19
    If saving to a file, call tts.save() directly — the simplest case.
  • 20–22

🚀 Step 4 — Wiring It All Together

python 
def main():
    parser = build_parser()
    args = parser.parse_args()

    try:
        text = read_input(args.source)
    except SystemExit as e:
        parser.error(str(e))

    if not text.strip():
        parser.error("Input text is empty.")

    if args.engine == "pyttsx3":
        speak_pyttsx3(
            text,
            output=args.output,
            voice=args.voice,
            rate=args.rate,
            volume=args.volume,
        )
    else:
        speak_gtts(text, output=args.output, voice=args.voice or "en")

    if args.output:
        print(f"Saved: {args.output}")

if __name__ == "__main__":
    main()

Lesson 9 — Full Project & Best Practices

The

The final lesson builds a complete, production-style project: an audiobook generator that reads a long text file, splits it into chapters, generates one MP3 per chapter with progress tracking, and writes a manifest file. Along the way, we cover the best practices that separate a quick script from a tool you'd actually ship.

🎯 What We're Building

Input: A plain-text file with chapters marked by lines like ## Chapter 1: The Beginning.

Output: A directory containing one MP3 per chapter (01-the-beginning.mp3, etc.), plus a manifest.json describing what was generated.

Features: Chapter detection, safe filename generation, chunked synthesis for long chapters, resume support (skip chapters already generated), progress reporting, and proper error handling.

📚 Step 1 — Parse the Chapters

python 
import re
from pathlib import Path
from dataclasses import dataclass, field

@dataclass
class Chapter:
    number: int
    title: str
    body: str
    slug: str = ""

    def __post_init__(self):
        # Safe, filesystem-friendly slug from the title
        s = re.sub(r"[^a-z0-9]+", "-", self.title.lower()).strip("-")
        self.slug = f"{self.number:02d}-{s[:40]}"

def parse_chapters(text):
    pattern = re.compile(r"^##\s*Chapter\s+(\d+)\s*[:\-–]\s*(.+)$", re.MULTILINE)
    matches = list(pattern.finditer(text))
    if not matches:
        # No chapter markers: treat entire file as one chapter
        return [Chapter(1, "Full Text", text.strip())]

    chapters = []
    for i, m in enumerate(matches):
        number = int(m.group(1))
        title = m.group(2).strip()
        start = m.end()
        end = matches[i + 1].start() if i + 1 < len(matches) else len(text)
        chapters.append(Chapter(number, title, text[start:end].strip()))
    return chapters

🎙️ Step 2 — Synthesize Each Chapter with Resume Support

python 
import json, sys
from pathlib import Path

def chunk_text(text, max_chars=4500):
    sentences = re.split(r"(?<=[.!?])\s+", text)
    chunks, current = [], ""
    for s in sentences:
        if len(current) + len(s) + 1 <= max_chars:
            current = (current + " " + s).strip()
        else:
            if current:
                chunks.append(current)
            current = s
    if current:
        chunks.append(current)
    return chunks

def synthesize_chapter(chapter, out_dir, lang="en", force=False):
    out_path = out_dir / f"{chapter.slug}.mp3"
    if out_path.exists() and not force:
        print(f"  ↻ Skipping {out_path.name} (already exists)")
        return out_path

    from gtts import gTTS
    chunks = chunk_text(chapter.body)

    if len(chunks) == 1:
        gTTS(text=chunks[0], lang=lang).save(str(out_path))
    else:
        # Multiple chunks: synthesize each, then concatenate with pydub
        import tempfile, os
        from pydub import AudioSegment
        combined = AudioSegment.empty()
        for i, chunk in enumerate(chunks):
            with tempfile.NamedTemporaryFile(suffix=".mp3", delete=False) as f:
                tmp = f.name
            try:
                gTTS(text=chunk, lang=lang).save(tmp)
                combined += AudioSegment.from_mp3(tmp)
            finally:
                os.unlink(tmp)
        combined.export(str(out_path), format="mp3")

    return out_path
  • 1–2
    json (for the manifest later) and Path.
  • 4
    chunk_text(text, max_chars=4500) — Same function as Lesson 7, but with a higher limit (4,500) because Google TTS accepts longer chunks than most engines.
  • 15
    def synthesize_chapter(chapter, out_dir, lang="en", force=False): — force allows regenerating existing files; otherwise resume-skip.
  • 16
    out_path = out_dir / f"{chapter.slug}.mp3" — Build the full output path using Path / str.
  • 17–19
    Resume logic: if the file exists and force is False, print a skip message and return. This makes the tool re-runnable — a crash mid-batch means you resume where you left off instead of re-generating everything.
  • 21
    from gtts import gTTS — Lazy import, keeping the function importable even if gTTS isn't installed.
  • 22
    chunks = chunk_text(chapter.body) — Split into API-safe pieces.
  • 24–25
    Fast path: if there's only one chunk, synthesize directly to the output path — no temp files needed.
  • 26–38
    Multi-chunk path: synthesize each chunk to a temp file, load it as a pydub AudioSegment, and accumulate into combined via +=. The += operator on AudioSegment concatenates audio in-place.
  • 33–37
    try/finally ensures the temp file is deleted even if MP3 loading fails. combined += requires the temp MP3 to be fully readable, so the whole chunk must be present first.
  • 38
    combined.export(str(out_path), format="mp3") — Write the concatenated audio as one MP3. Requires ffmpeg installed (see Lesson 4).
💡 Why concatenate chunks instead of one big gTTS call? gTTS silently splits long text internally, but it doesn't give you control over where those splits happen — sometimes mid-word or mid-sentence, causing awkward pauses. Explicit sentence-boundary chunking sounds noticeably better and also keeps individual requests short enough to retry cheaply on network errors.

📦 Step 3 — Orchestration and Manifest

python 
def generate_audiobook(input_path, out_dir, lang="en", force=False):
    input_path = Path(input_path)
    out_dir = Path(out_dir)
    out_dir.mkdir(parents=True, exist_ok=True)

    if not input_path.exists():
        sys.exit(f"Input not found: {input_path}")

    text = input_path.read_text(encoding="utf-8")
    chapters = parse_chapters(text)
    print(f"Found {len(chapters)} chapter(s) in {input_path.name}")

    generated = []
    for ch in chapters:
        print(f"[{ch.number}/{len(chapters)}] {ch.title}")
        try:
            path = synthesize_chapter(ch, out_dir, lang=lang, force=force)
            generated.append({
                "number": ch.number,
                "title": ch.title,
                "file": path.name,
                "chars": len(ch.body),
            })
        except Exception as e:
            print(f"  ✗ Failed: {e}")
            continue

    manifest = {
        "source": input_path.name,
        "language": lang,
        "chapters": generated,
        "total_chapters": len(generated),
    }
    (out_dir / "manifest.json").write_text(
        json.dumps(manifest, indent=2, ensure_ascii=False),
        encoding="utf-8",
    )
    print(f"\nDone. {len(generated)} file(s) in {out_dir}/")
    print(f"Manifest: {out_dir / 'manifest.json'}")
  • 1–3
    Coerce both paths to Path objects, then create the output directory. parents=True creates intermediate dirs (book/chapters/); exist_ok=True avoids errors if it already exists.
  • 5–6
    Fail fast if the input doesn't exist. sys.exit() with a message is the cleanest way to signal a fatal CLI error.
  • 8–10
    Read the whole file, parse chapters, print a summary. Users need confirmation the tool saw the right file and the expected chapter count.
  • 12–13
    generated = [] then loop over chapters. The progress line [1/10] Title is essential UX for anything longer than a few seconds.
  • 15–21
    Call synthesize_chapter, then append a metadata dict to generated. The chars field gives the user a rough sense of chapter length.
  • 22–24
    Error containment: except Exception as e: print(...); continue — one failed chapter doesn't abort the whole book. This is the right call for long batch operations; users would rather have 9 of 10 chapters than 0.
  • 26–31
    Build the manifest dict. It records source, language, chapter list, and total. This becomes the metadata that downstream tools (players, catalogs) can rely on.
  • 32–35
    Write manifest.json with indent=2 (human-readable) and ensure_ascii=False (preserves Unicode titles — important for non-English books).
  • 36–37
    Final summary, including the manifest path so the user knows where to look.

✅ Best Practices — What Separates a Script from a Tool

1. Fail loudly, fail early. Check for missing files, empty input, and missing dependencies before doing any real work. sys.exit(f"Input not found: {path}") beats a stack trace 30 seconds into processing.

2. Idempotent by default. The tool should be safe to re-run. Resume-skip (if out_path.exists() and not force) makes crashes cheap to recover from.

3. Contain errors per unit. One bad chapter shouldn't kill the whole book. Wrap each iteration in try/except and continue.

4. Record what you did. The manifest.json is the source of truth — it lets other tools index the output, and it lets you check what succeeded later.

5. Never hardcode secrets. AWS keys, API tokens — use environment variables or aws configure. Never commit secrets to git.

6. Choose the right engine per task. Offline speech (pyttsx3) for privacy and speed; cloud (gTTS, Polly) for natural voice and language coverage.

7. Chunk at sentence boundaries. Never split mid-word. The regex lookbehind pattern re.split(r"(?<=[.!?])\s+", text) is the workhorse.

8. Clean up temp files. Use tempfile.NamedTemporaryFile(delete=False) plus try/finally: os.unlink(...) so a crash never leaves garbage behind.

9. Log progress. print(f"[{i}/{n}] {title}") is one line of code and worth its weight in gold when processing takes minutes.

10. Respect rate limits and terms. gTTS and Polly both have quotas. Add time.sleep(1) between requests in batch jobs; use Polly's async API for very long jobs.

✂️ Chunking Long Text

python 
import re

def chunk_text(text, max_chars=500):
    sentences = re.split(r"(?<=[.!?])\s+", text)
    chunks, current = [], ""
    for s in sentences:
        if len(current) + len(s) + 1 <= max_chars:
            current = (current + " " + s).strip()
        else:
            if current:
                chunks.append(current)
            current = s
    if current:
        chunks.append(current)
    return chunks
