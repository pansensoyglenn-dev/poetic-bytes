Lesson 1 — What Is Web Scraping, and Is It Legal?

Web scraping is the practice of writing a program that automatically fetches web pages and extracts structured information from them. Instead of copy-pasting prices, job listings, or product reviews by hand, a script does it for you — consistently, and at scale.

Every website you open sends its content as HTML — a text document full of tags that mark up headings, paragraphs, links, and data tables. A scraper downloads that HTML and parses it into a tree of elements, then pulls out the pieces you care about. The output is usually a list or table you can save to CSV, a database, or feed into a spreadsheet.

Key idea: Your browser does three things when you load a page — sends an HTTP request, receives HTML, and renders it visually. A scraper does the first two, then reads the raw HTML instead of drawing it on screen.

⚖️ Is Scraping Legal? The Short Answer

Scraping public data is legal in many jurisdictions (including the US, per the hiQ v. LinkedIn and Van Buren v. United States rulings), but there are important limits:

  • Always check robots.txt — a file at example.com/robots.txt that tells bots which paths they may fetch. If it says Disallow: /private/, don't scrape that path.
  • Read the Terms of Service — some sites explicitly prohibit automated access. Violating ToS can get your IP banned and, in some cases, has led to civil suits.
  • Don't scrape personal data — GDPR and similar laws restrict collecting names, emails, or anything that identifies a person without consent.
  • Don't hammer the server — add delays between requests. A scraper that sends 100 requests per second is effectively a denial-of-service attack.
  • Never bypass login walls or CAPTCHAs — that's unauthorized access in most legal interpretations.
Rule of thumb: If the data is behind a login, behind a paywall, or the site's robots.txt disallows it — don't scrape it. Build with respect and you'll rarely run into trouble.

🧪 Runnable Example — Hello, Web

This first example fetches a small test page and prints its status code and title. It doesn't extract anything yet — it just proves you can reach the web from Python.

import requests
from bs4 import BeautifulSoup

url = "https://quotes.toscrape.com"
response = requests.get(url)

print("Status code:", response.status_code)
print("Content type:", response.headers.get("Content-Type"))

soup = BeautifulSoup(response.text, "html.parser")
print("Page title:", soup.title.string)
Line-by-line explanation
  • 1
    import requests — Loads the requests library into memory. requests is the standard Python tool for making HTTP calls (GET, POST, etc.). You'll install it once with pip install requests.
  • 2
    from bs4 import BeautifulSoup — Imports only the BeautifulSoup class from the bs4 package. Importing just the class (instead of import bs4) means you can write BeautifulSoup(...) instead of bs4.BeautifulSoup(...).
  • 3
    url = "..." — Stores the page address in a variable. Assigning it to a variable up front (rather than inline) makes it easy to change later or loop over multiple URLs.
  • 4
    response = requests.get(url) — Sends an HTTP GET request to that URL. The returned response object holds the status code, headers, and body (the HTML). This is the actual network call.
  • 5
    print("Status code:", response.status_code) — response.status_code is the HTTP status: 200 means success, 404 means not found, 403 means forbidden, 500 means server error. Always check this — a scraper that assumes 200 will silently fail on error pages.
  • 6
    print("Content type:", response.headers.get("Content-Type")) — The headers dictionary contains metadata the server sent back. Content-Type usually reads text/html; charset=utf-8, confirming you got HTML and not, say, JSON or a PDF.
  • 7
    soup = BeautifulSoup(response.text, "html.parser") — Creates a parse tree from the raw HTML string. response.text is the body as a Python string. "html.parser" is the parser — it's built into Python so needs no extra install (unlike lxml, which is faster).
  • 8
    print("Page title:", soup.title.string) — soup.title grabs the first <title> tag. .string returns its text content. For this page it prints Quotes to Scrape.

Lesson 2 — Your First HTTP Request (Anatomy of requests)

Before BeautifulSoup can help you, you need HTML in memory. That's the job of requests. This lesson digs into what happens under the hood when you call requests.get(), and how to read the response object correctly.

🔎 The Response Object — What's Inside

Every call returns a Response object with these key attributes:

  • response.status_code — the HTTP status number (200, 404, etc.).
  • response.text — the body decoded as a string using the charset in the response headers.
  • response.content — the body as raw bytes (use this for images, PDFs, or when text encoding is ambiguous).
  • response.headers — a dict of response headers.
  • response.url — the final URL after any redirects.
  • response.json() — parses the body as JSON and returns a Python dict.

🧪 Runnable Example — Inspect a Response

import requests

url = "https://httpbin.org/html"
response = requests.get(url, timeout=10)

print("Status:", response.status_code)
print("Final URL:", response.url)
print("Encoding:", response.encoding)
print("Body length:", len(response.text), "chars")
print("First 200 chars:")
print(response.text[:200])
Line-by-line explanation
  • 1
    import requests — Same as Lesson 1. This is now muscle memory.
  • 3
    url = "https://httpbin.org/html" — httpbin is a free service that echoes HTTP requests back — perfect for testing without hitting a real site. /html returns a small, valid HTML page.
  • 4
    response = requests.get(url, timeout=10) — The timeout=10 argument is critical: if the server doesn't respond within 10 seconds, requests raises a Timeout exception. Without a timeout, your script could hang forever. Never make a request without a timeout in production.
  • 6
    print("Status:", response.status_code) — Prints 200. httpbin always returns 200 for valid paths, so this is a good sanity check that the request went through.
  • 7
    print("Final URL:", response.url) — Shows the URL after any redirects. If http:// redirected to https://, this would show the final one. Useful for detecting login redirects.
  • 8
    print("Encoding:", response.encoding) — Prints something like utf-8. This is the charset requests guessed from headers. If the guess is wrong (rare, but happens), call response.encoding = "utf-8" before reading .text to force it.
  • 9
    print("Body length:", len(response.text), "chars") — Reports how many characters the body contains. A length of 0 or a few hundred usually indicates an error page or a block — worth checking.
  • 10
    print("First 200 chars:") — A label for the next output line. Pure readability.
  • 11
    print(response.text[:200]) — Slices the first 200 characters of the body. The [:200] is Python slicing — characters 0 through 199. This lets you visually confirm the HTML looks right before parsing.

📋 Common Arguments to requests.get()

requests.get(
    url,
    params={"q": "python", "page": 2},
    headers={"User-Agent": "Mozilla/5.0"},
    timeout=10,
    allow_redirects=True,

  • →
    params — A dict that gets URL-encoded into the query string. The example above becomes ?q=python&page=2. Use this instead of manually building query strings.
  • →
    headers — Extra HTTP headers to send. User-Agent is the most important — see Lesson 8.
  • →
    timeout — Max seconds to wait. Float allowed (e.g. 2.5).
  • →

Lesson 3 — Inspecting HTML: How to Find the Data You Want

Before you can scrape a page, you have to know what its HTML looks like. This lesson teaches the browser DevTools workflow — how to open a page, find the element containing your target data, and identify the tag, class, or id that uniquely selects it.

🖱️ The DevTools Workflow

  1. Open the page in Chrome, Firefox, or Edge.
  2. Right-click on the data you want (e.g. a product price) → Inspect.
  3. The Elements panel opens, highlighting that element in the DOM tree.
  4. Look at its tag — is it <span class="price">$19.99</span>? Note the tag, class, and any parent classes.
  5. Check whether that class is unique. Click Ctrl+F in DevTools and search for .price to count matches.
  6. If it appears many times, refine: use a parent selector like .product-card .price.

🧬 Anatomy of a Real HTML Page

Here's a simplified version of what a listing page's HTML looks like under the hood. Study the structure — this is what every scraper must navigate.

<!-- A single product card -->
<div class="product-card" data-id="42">
    <h3 class="product-title">Wireless Headphones</h3>
    <span class="product-price">$89.99</span>
    <a href="/product/42" class="product-link">View details</a>
</div>
What to notice: The outer div.product-card groups everything about one product. Inside it, three sibling elements hold the title, price, and link. The data-id="42" is a custom attribute — useful data that's often overlooked. Scrapers typically iterate over .product-card containers and pull out the children.

🧪 Runnable Example — Fetch and Print the Raw HTML

Let's fetch a real page and print the outerHTML of a specific element. This shows you exactly how the browser sees it.

import requests
from bs4 import BeautifulSoup

url = "https://quotes.toscrape.com"
response = requests.get(url, timeout=10)
soup = BeautifulSoup(response.text, "html.parser")

# Find the first quote block
first_quote = soup.select_one(".quote")
if first_quote:
    print(first_quote.prettify()[:600])
else:
    print("No .quote element found.")
Line-by-line explanation
  • 1–2
    import requests and from bs4 import BeautifulSoup — The two imports every scraper starts with.
  • 4
    url = "https://quotes.toscrape.com" — This is a site designed for scraping practice. Its HTML is deliberately clean and stable, so it's perfect for learning.
  • 5
    response = requests.get(url, timeout=10) — Download the page. The timeout=10 ensures we don't wait forever.
  • 6
    soup = BeautifulSoup(response.text, "html.parser") — Parse the HTML into a navigable tree. From here on, soup is our queryable object.
  • 8
    # Find the first quote block — A comment. Good practice when writing scrapers — you'll revisit this code in three months and forget why each line exists.
  • 9
    first_quote = soup.select_one(".quote") — select_one() finds the first element matching the CSS selector .quote. It returns a Tag object or None. Use .select() (no "one") for a list of all matches.
  • 10
    if first_quote: — A safety check. If select_one returned None, calling .prettify() on it would crash with AttributeError: 'NoneType' object has no attribute 'prettify'. Always check for None on optional elements.
  • 11
    print(first_quote.prettify()[:600]) — .prettify() returns the element as nicely-indented HTML — much more readable than a single-line dump. The [:600] slices the first 600 characters so the output isn't overwhelming.
  • 12–13
    else: print("No .quote element found.") — If the element wasn't found (site changed structure, blocked request, wrong page), we print a clear message instead of crashing. This is defensive coding.

🛠️ Quick Reference — Selector Types

These are the selectors you'll use constantly. Memorize this small table:
  • tag
    soup.select("h1") — All <h1> tags anywhere in the document.
  • .class
    soup.select(".product-title") — All elements with class="product-title". The leading dot means "class".
  • #id
    soup.select("#main-content") — The unique element with id="main-content". The hash means "id".
  • A B
    soup.select("div.product-card h3") — All <h3> that are descendants of a div.product-card. This is the most common pattern for scoping extraction.
  • A > B
    soup.select("div.product-card > h3") — Only <h3> whose direct parent is div.product-card. Use when elements are nested at a specific depth.
  • [attr]
    soup.select("a[href]") — All <a> tags that have an href attribute.
  • [attr="v"]
    soup.select("a[href='/product/42']") — Elements with an exact attribute value.
  • A, B
    soup.select("h1, h2") — Comma means "or" — returns all <h1> and all <h2>.

Lesson 4 — BeautifulSoup Basics: Navigating the Parse Tree

BeautifulSoup turns a flat HTML string into a tree of Python objects. Once parsed, you can navigate the tree just like a filesystem — move from parent to child, query siblings, filter by attribute. This lesson covers the core navigation API that everything else builds on.

🌳 Four Object Types You Need to Know

🏷️

Tag

Represents an HTML element — e.g. <p class="x">Hi</p>. Has attributes like .name, .attrs, .text.

📝

NavigableString

The text inside a tag. Behaves like a string. Returned by tag.string or tag.get_text().

🔗

BeautifulSoup

The top-level document object. Behaves like a Tag representing the whole page.

💭

Comment

HTML comments (<!-- ... -->). Subclass of NavigableString. Usually you want to skip these.

🔍 find vs find_all vs select

These three methods are the heart of BS4. Understanding the difference saves you hours of confusion:

  • find(name, attrs) — Returns the first matching Tag, or None.
  • find_all(name, attrs) — Returns a list of all matching Tags. Empty list if none found.
  • select(css_selector) — Returns a list of Tags matching a CSS selector. More powerful than find_all for complex queries.
  • select_one(css_selector) — Returns the first match, or None.

🧪 Runnable Example — Extract All Quotes and Authors

This is the classic "hello world" of scraping. It extracts every quote and author from the test site.

import requests
from bs4 import BeautifulSoup

url = "https://quotes.toscrape.com"
soup = BeautifulSoup(requests.get(url, timeout=10).text, "html.parser")

quotes = soup.find_all("div", class_="quote")
print(f"Found {len(quotes)} quotes")

for q in quotes[:3]:
    text = q.find("span", class_="text").get_text(strip=True)
    author = q.find("small", class_="author").get_text(strip=True)
    print(f"{text} — {author}")
Line-by-line explanation
  • 1–2
    Imports — same as before.
  • 4
    url = "https://quotes.toscrape.com" — The practice site.
  • 5
    soup = BeautifulSoup(requests.get(url, timeout=10).text, "html.parser") — Combines three operations into one line: (a) requests.get() downloads the page, (b) .text gives the HTML as a string, (c) BeautifulSoup(...) parses it. If you find this hard to read, split it into three lines. Readability > brevity.
  • 7
    quotes = soup.find_all("div", class_="quote") — Finds every <div> whose class attribute equals "quote". Note the trailing underscore on class_ — class is a Python keyword, so BeautifulSoup uses class_ (with underscore) to avoid the conflict. Returns a list of Tag objects.
  • 8
    print(f"Found {len(quotes)} quotes") — len(quotes) tells you how many matches. This is a key diagnostic — if it prints 0, your selector is wrong. If it prints a huge number, you probably over-matched.
  • 10
    for q in quotes[:3]: — Loops through the first three quote blocks. The [:3] slice is just for compact output — remove it in production to process all quotes.
  • 11
    text = q.find("span", class_="text").get_text(strip=True) — Inside each quote block, find the <span class="text"> tag. .get_text(strip=True) returns the text content with leading/trailing whitespace removed. Without strip=True, you'd get lots of \n padding.
  • 12
    author = q.find("small", class_="author").get_text(strip=True) — Same pattern, but for the author. Notice that q.find() (not soup.find()) scopes the search inside the current quote — it won't accidentally match an author from a different quote. This is the fundamental "scope then extract" pattern.
  • 13
    print(f"{text} — {author}") — Formats each result with an em-dash separator. In an f-string, {text} and {author} are replaced with their values.
💡 Why q.find() and not soup.find()? Because you want to extract the title/author pairing from the same product card. If you used soup.find() for both, you'd get the first match on the page every time. Always scope your extraction to a parent container.

🔧 Other Ways to Navigate the Tree

# Assume you have a Tag called `tag`
tag.parent          # Immediate parent Tag
tag.parents         # Generator of all ancestors
tag.children        # Generator of direct children
tag.descendants     # Generator of ALL descendants
tag.next_sibling    # Next sibling Tag
tag.previous_sibling
tag.find_next("a")  # Next  after this tag
tag.find_parent("div") # Nearest ancestor
  • →
    .parent — Walk up the tree. Useful when you've found a small element and need its surrounding container.
  • →
    .children — Iterate over direct children only. .descendants includes grandchildren and deeper.
  • →
    .next_sibling — Move sideways. Frequently used in table scraping to find the next <td> after a <th>.
  • →
    .find_parent("div") — Walk up until you find a <div>. Handy when a nested element is uniquely identifiable.

Lesson 5 — CSS Selectors & find_all in Depth

In Lesson 3 you learned what CSS selectors are. In Lesson 4 you used find_all with class_. This lesson brings them together: when to use find_all, when to use select, and how to write robust selectors that don't break when the site updates.

⚖️ find_all vs select — Which to Use?

Rule of thumb: Use find_all when you're matching by a single tag + class combination. Use select when you need descendant combinators (A B), pseudo-selectors, or multiple conditions joined together.
  • 1
    soup.find_all("div", class_="card") — Simple and fast. Matches all <div class="card">.
  • 2
    soup.select("div.card") — Same result, CSS syntax. Slightly slower but more flexible once you add combinators.
  • 3
    soup.select("div.card > a[href]") — find_all can't express this directly; you'd have to do find_all("div", class_="card") then iterate and call .find_all("a", href=True). select does it in one call.
  • 4
    soup.find_all("a", href=re.compile("^/product/")) — Passing a compiled regex as an attribute value is a find_all-only trick — very useful for matching URL patterns.

🧪 Runnable Example — Scoping with Parent Selectors

Let's scrape product cards from a listing page. We'll use select with a parent selector to scope extraction to each card, then pull out title, price, and link.

import requests
from bs4 import BeautifulSoup

url = "https://quotes.toscrape.com"
soup = BeautifulSoup(requests.get(url, timeout=10).text, "html.parser")

cards = soup.select("div.quote")
print(f"Cards found: {len(cards)}")

for card in cards[:2]:
    title  = card.select_one("span.text")
    author = card.select_one("small.author")
    tags   = [t.get_text(strip=True) for t in card.select("a.tag")]

    print("TITLE:", title.get_text(strip=True) if title else "(none)")
    print("AUTHOR:", author.get_text(strip=True) if author else "(none)")
    print("TAGS:", ", ".join(tags))
    print("-" * 50)
Line-by-line explanation
  • 1–2
    Standard imports.
  • 4–5
    Fetch and parse the page as before.
  • 7
    cards = soup.select("div.quote") — Uses CSS selector syntax. div.quote means "a <div> with class quote". Same result as soup.find_all("div", class_="quote") from Lesson 4 — choose whichever reads better to you.
  • 8
    print(f"Cards found: {len(cards)}") — Sanity check. Empty list here means the site changed or you were blocked.
  • 10
    for card in cards[:2]: — Loop over the first two. In a real scraper, you'd loop over all cards.
  • 11
    title = card.select_one("span.text") — Inside this card, find the first <span class="text">. select_one returns None if no match — that's why we check for None below.
  • 12
    author = card.select_one("small.author") — Same pattern. The small.author selector means "a <small> element with class author". If the site used a <span class="author">, you'd change it to span.author.
  • 13
    tags = [t.get_text(strip=True) for t in card.select("a.tag")] — A list comprehension. card.select("a.tag") returns all <a> tags with class tag. For each t, we call t.get_text(strip=True) to extract its text. The whole expression builds a list like ["change", "deep-thoughts", "thinking"].
  • 15
    print("TITLE:", title.get_text(strip=True) if title else "(none)") — Ternary expression: "if title is not None, call .get_text() on it; otherwise print (none)". This prevents an AttributeError when the title is missing.
  • 16
    Same pattern for author — null-safe extraction.
  • 17
    print("TAGS:", ", ".join(tags)) — ", ".join(tags) joins the list of strings with , in between — producing change, deep-thoughts, thinking. If the list is empty, join returns "".
  • 18
    print("-" * 50) — Prints 50 hyphens as a divider. "-" * 50 in Python repeats the string 50 times. Useful for readability in log output.
💡 Null-safety is the most important habit in scraping. Any element you didn't see on the page when you tested may be missing on other pages. Always use if element checks or a default value.

🎯 Selector Cheat Sheet

# Class
soup.select(".price")                # all elements with class="price"

# ID (unique)
soup.select("#main")                 # the element with id="main"

# Descendant
soup.select(".product-card .price")  # .price anywhere inside a .product-card

# Direct child
soup.select(".product-card > h3")    # h3 that is direct child of .product-card

# Attribute
soup.select("a[href]")                #  with any href
soup.select("a[data-id='42']")        # exact attribute match

# Pseudo-classes
soup.select("li:first-child")         # first 
  •  in each list
soup.select("li:nth-child(2n)")       # every other

    Lesson 6 — Extracting Attributes: Links, Images, and Data

    So far you've extracted text. But the most valuable data on a page is often stored in attributes: href on links, src on images, data-* on interactive elements, datetime on time tags. This lesson covers all the ways to get attribute values out of a Tag object.

    📦 Three Ways to Read an Attribute

    • 1
      tag["href"] — Dictionary access. Raises KeyError if the attribute doesn't exist. Only use this when you're certain the attribute is present.
    • 2
      tag.get("href") — Safe dictionary access. Returns None if missing. This is the version you should use 95% of the time.
    • 3
      tag.get("href", "/") — Safe access with a default value. Useful when you want a fallback.
    • 4
      tag.attrs — The full attribute dictionary. Useful for inspecting what's available.

    🧪 Runnable Example — Absolute URLs from Relative Hrefs

    A super common problem: the site uses relative URLs like href="/product/42", but you want the absolute URL https://example.com/product/42. Here's the pattern:

    import requests
from bs4 import BeautifulSoup

    import requests
from bs4 import BeautifulSoup
from urllib.parse import urljoin

base_url = "https://quotes.toscrape.com"
soup = BeautifulSoup(requests.get(base_url, timeout=10).text, "html.parser")

# Find all author links and print their absolute URLs
author_links = soup.select("div.quote span a")
print(f"Found {len(author_links)} author links")

for link in author_links[:3]:
    relative = link.get("href")
    absolute = urljoin(base_url, relative)
    print(f"Relative: {relative}")
    print(f"Absolute: {absolute}")
    print()

    • 1–2
      Standard imports as before.
    • 3
      from urllib.parse import urljoin — urljoin is a standard library function that correctly resolves relative URLs against a base. It handles ./, ../, absolute paths, and full URLs — everything.
    • 5
      base_url = "https://quotes.toscrape.com" — The base to resolve against. It's the URL we fetched, which is the correct base for all links on that page.
    • 6

    Lesson 7 — Handling Pagination: Scrape Every Page, Not Just One

    Most real sites split data across many pages. A scraper that only reads page 1 is a toy — a scraper that walks every page is a tool. This lesson covers the three common pagination patterns and how to write a loop that handles all of them safely.

    🔢 The Three Pagination Patterns

    🔗

    1. Next-link pattern

    Each page contains a "Next →" link. Find it, follow it, repeat until it's absent. Cleanest pattern.

    🔢

    2. Page-number pattern

    URLs are ?page=1, ?page=2, etc. Loop over a range and construct each URL.

    ♾️

    3. Infinite scroll (API)

    JavaScript fires requests as you scroll. Usually requires Playwright or intercepting the API. Covered in Lesson 11.

    🧪 Runnable Example — Walk All Pages with the Next-Link Pattern

    quotes.toscrape.com uses the next-link pattern. Each page ends with a <li class="next"><a href="/page/2/">Next</a></li>. Here's the full loop that scrapes every page until there is no next link:

    response = requests.get(url, timeout=10)
    soup = BeautifulSoup(response.text, "html.parser")

        text   = q.select_one("span.text")
        author = q.select_one("small.author")
        if text and author:
            all_quotes.append({
                "text":   text.get_text(strip=True),
                "author": author.get_text(strip=True),
            })

    if next_link and next_link.get("href"):
        url = urljoin(base, next_link["href"])
        page += 1
    else:
        url = None

print(f"\nTotal quotes scraped: {len(all_quotes)}")
print("First:", all_quotes[0] if all_quotes else "none")

    Lesson 8 — Headers, User-Agents & Rate Limiting

    The fastest way to get your scraper blocked is to make requests that look obviously automated. This lesson covers how to present yourself properly (headers), how to slow down to a polite pace (rate limiting), and how to detect and recover from being blocked.

    🪪 Why Headers Matter — The User-Agent

    By default, Python's requests library sends User-Agent: python-requests/2.31.0. Every server admin knows this string, and many sites immediately block or CAPTCHA it. Setting a realistic User-Agent makes your requests look like a browser. Note: this isn't about hiding — it's about being treated the same as a normal visitor.

    Important: Setting a browser User-Agent does not make scraping "legal" if the site prohibits it in its ToS. The legal and ethical checks from Lesson 1 still apply. Headers just prevent your legitimate traffic from being dropped by automated anti-bot rules.

    Lesson 9 — Saving Scraped Data to CSV and JSON

    Use CSV when: the data is a flat table, you'll open it in Excel/Sheets, or you're handing it to a non-programmer.

    Lesson 10 — Robust Error Handling for Production Scrapers

    A scraper that works on page 1 but crashes on page 47 is not ready. Real-world scraping hits network timeouts, HTTP errors, missing HTML elements, and unexpected page content. This lesson teaches you the four patterns that make scrapers resilient: try/except around requests, null-safe extraction, retry with backoff, and per-item error recovery.

    🛡️ The Four Layers of Scraper Resilience

    1️⃣

    Network layer

    try/except around every requests.get() for timeouts, connection errors, DNS failures.

    2️⃣

    HTTP layer

    Check status_code == 200 before parsing. Non-200 responses don't have useful HTML.

    3️⃣

    Extraction layer

    Null checks on every .select_one() result before calling .get_text() or [].

    4️⃣

    Retry layer

    Transient failures (timeouts, 5xx) should be retried with exponential backoff — not abandoned.

    🧪 Runnable Example — A Resilient Fetch-and-Extract Function

    This is the pattern you should copy into every scraper. It handles each failure layer explicitly and returns None or a partial record rather than crashing.

    import requests, time
from bs4 import BeautifulSoup
from requests.exceptions import RequestException, Timeout, HTTPError

def fetch(url, retries=3, backoff=2.0, timeout=10):
    for attempt in range(1, retries + 1):
        try:
            response = requests.get(url, timeout=timeout)
            response.raise_for_status()
            return response
        except HTTPError as e:
            print(f"  [{attempt}] HTTP {response.status_code} — {e}")
            if 400 <= response.status_code < 500:
                return None
        except Timeout:
            print(f"  [{attempt}] Timeout after {timeout}s")
        except RequestException as e:
            print(f"  [{attempt}] Request error: {e}")

        if attempt < retries:
            wait = backoff ** attempt
            print(f"  retrying in {wait}s...")
            time.sleep(wait)

    print(f"  Giving up on {url}")
    return None

# Usage — parse only if we actually got HTML
response = fetch("https://quotes.toscrape.com")
if response is not None:
    soup = BeautifulSoup(response.text, "html.parser")
    print("Got page, title:", soup.title.string)
    Line-by-line explanation

      Imports. The requests.exceptions module has specific exception classes. Catching RequestException (the base class) catches everything network-related, while Timeout and HTTPError are more specific.
    • 5
      def fetch(url, retries=3, backoff=2.0, timeout=10): — A reusable helper. Default arguments mean callers don't have to specify everything every time.
    • 6
      for attempt in range(1, retries + 1): — Attempt 1, 2, 3. Not 0-based, because "attempt 0" reads badly in logs.
    • 7
      try: — All network code lives inside the try. Anything that raises will jump to an except clause.
    • 8
      response = requests.get(url, timeout=timeout) — The actual request. If it takes longer than timeout, a Timeout is raised.
    • 9
      response.raise_for_status() — The single most important line. This raises an HTTPError for 4xx and 5xx statuses. Without it, requests happily returns a 404 as a "successful" Response — and you'd try to parse an error page as if it were your content.
    • 10
      return response — Success. Exit the function immediately. No further attempts needed.
    • 11–13
      except HTTPError as e: — Catches 4xx/5xx. e is the exception; response.status_code tells us which. If it's 4xx (client error — bad URL, blocked, forbidden), retrying won't help, so return None immediately. If it's 5xx (server error — temporary), fall through to the retry logic.
    • 14–15
      except Timeout: — Timeouts are always worth retrying; the server may just be having a bad moment.
    • 16–17

Getting this distinction right saves you from wasting retries on impossible requests and from giving up on requests that would have succeeded.

    🧩 Per-Item Error Recovery — Don't Let One Bad Row Kill the Batch

    Even with network handling in place, individual items can fail extraction. A missing element, a malformed number, a typo in one card — these shouldn't stop the whole scrape. Wrap extraction in its own try/except per item:

        text   = card.select_one("span.text").get_text(strip=True)
        author = card.select_one("small.author").get_text(strip=True)
        results.append({"text": text, "author": author})
    except AttributeError as e:
        errors.append(f"Skipped card: {e}")

    Lesson 11 — Scraping JavaScript-Rendered Sites with Playwright

    Everything up to now assumed the data is in the HTML that the server sends. That's true for most static sites — but a growing number of modern sites (React, Vue, Svelte, Angular) ship an almost empty HTML shell and fill it in with JavaScript. If you requests.get() those sites, you'll get a page with a loading spinner and nothing else. Playwright solves this by running a real browser.

    🌐 Why requests Fails on SPA Sites

    Here's the difference:

    ✅

    Static site (works with requests)

    Server sends full HTML. requests.get() gets the same thing you see in View Source. Fast. Simple. BeautifulSoup parses it directly.

    ❌

    SPA site (needs a browser)

    Server sends <div id="root"></div> plus a JS bundle. The data appears only after JS runs. requests gets the empty shell — nothing to scrape.

    How to check: Open the site, right-click → View Page Source (or Ctrl+U). If the data is not in the source but is in the DevTools Elements panel — it's a JavaScript site. Use Playwright.

    🎭 Playwright — The Modern Browser Automation Tool

    Playwright controls real Chrome, Firefox, or WebKit. It's the current best-in-class tool for browser automation (better than older Selenium for most tasks — faster, more reliable, better async support). Install:

    # One-time install (in your terminal, not Python)
pip install playwright
playwright install chromium
    ⚠️ Playwright requires a browser binary download (~150MB). It's not available in the browser-based Pyodide runner — you must run these examples locally. The code below is educational; it will only work with a real Playwright installation.

    🧪 Example — Scrape a JS-Rendered Page

    Here's a minimal Playwright scraper that waits for content to load, extracts data, and closes the browser cleanly:

    from playwright.sync_api import sync_playwright

def scrape_dynamic_page(url):
    with sync_playwright() as p:
        browser = p.chromium.launch(headless=True)
        page = browser.new_page()
        page.goto(url, wait_until="networkidle")

        # Wait for the data to appear in the DOM
        page.wait_for_selector(".product-card", timeout=10000)

        cards = page.query_selector_all(".product-card")
        results = []
        for card in cards:
            title = card.query_selector(".product-title")
            price = card.query_selector(".product-price")
            results.append({
                "title": title.inner_text() if title else None,
                "price": price.inner_text() if price else None,
            })

        browser.close()
        return results

# results = scrape_dynamic_page("https://example-spa.com/products")
# print(results)

    • 3

    • 4

    • 5

    • 6

    • 7

    • 23

    ⚖️ requests vs Playwright — When to Use Which

    Always try requests first. It's 20× faster, uses 100× less memory, and doesn't require a browser download. Only reach for Playwright when you've confirmed the data isn't in the raw HTML.
    • 1
      Try requests: fetch the page, search the raw HTML for a known phrase (like the product name). If it's there, use requests + BS4.
    • 2
      Try the API: open DevTools → Network tab → filter to XHR/Fetch. Many SPAs call a JSON API behind the scenes. If you can find that endpoint, hit it directly with requests — you get clean JSON instead of fragile HTML. This is the single biggest "pro tip" for modern scraping.
    • 3
      Use Playwright: only if neither works — the page requires JS to render and there's no public API. Accept that it's slower and heavier.
    💡 Common mistake: jumping to Playwright for every site because it "just works." It's a 200MB browser download, takes 3–5 seconds per page load, and consumes hundreds of MB of RAM. For 90% of scraping tasks, requests + BeautifulSoup is the right tool. Choose based on evidence, not habit.

    Lesson 12 — Capstone Project: A Complete, Ethical Scraper

    This final lesson assembles every pattern from Lessons 1–11 into one production-quality scraper. We'll scrape all quotes from quotes.toscrape.com, save them to both CSV and JSON, log progress, handle errors, respect rate limits, and check robots.txt first.

    📋 The Full Project — Pulling Every Lesson Together

    Read the code, then the line-by-line breakdown below. Every line is a technique from an earlier lesson.

    import requests, csv, json, time, random
from bs4 import BeautifulSoup
from urllib.parse import urljoin, urlparse
from urllib.robotparser import RobotFileParser

BASE = "https://quotes.toscrape.com"

# 1. Respect robots.txt
def can_scrape(url):
    rp = RobotFileParser()
    rp.set_url(urljoin(url, "/robots.txt"))
    try:
        rp.read()
        return rp.can_fetch("*", url)
    except Exception:
        return False

# 2. Fetch with retries (from Lesson 10)
def fetch(url, retries=3):
    for attempt in range(1, retries + 1):
        try:
            r = requests.get(url, timeout=10,
                headers={"User-Agent": "PoeticBytes-Scraper/1.0 (+contact@example.com)"})
            r.raise_for_status()
            return r
        except requests.exceptions.RequestException as e:
            print(f"  attempt {attempt} failed: {e}")
            if attempt < retries:
                time.sleep(2 ** attempt)
    return None

# 3. Scrape with pagination, extraction, and per-item safety
def scrape_all():
    if not can_scrape(BASE):
        print("robots.txt disallows scraping — aborting.")
        return []

    records = []
    url, page = BASE, 1

    while url and page <= 20:
        print(f"[{page}] {url}")
        r = fetch(url)
        if r is None:
            break

        soup = BeautifulSoup(r.text, "html.parser")

        for card in soup.select("div.quote"):
            try:
                text   = card.select_one("span.text").get_text(strip=True)
                author = card.select_one("small.author").get_text(strip=True)
                tags   = [t.get_text(strip=True) for t in card.select("a.tag")]
                records.append({"text": text, "author": author, "tags": tags})
            except AttributeError:
                continue

        next_a = soup.select_one("li.next > a")
        url = urljoin(BASE, next_a["href"]) if next_a else None
        page += 1

        if url:
            delay = random.uniform(1.0, 2.0)
            print(f"  sleeping {delay:.2f}s")
            time.sleep(delay)

    return records

# 4. Save both formats
def save(records):
    if not records:
        print("No records to save.")
        return

    with open("quotes.csv", "w", newline="", encoding="utf-8") as f:
        writer = csv.DictWriter(f, fieldnames=["text", "author", "tags"])
        writer.writeheader()
        for rec in records:
            writer.writerow({**rec, "tags": "|".join(rec["tags"])})

    with open("quotes.json", "w", encoding="utf-8") as f:
        json.dump(records, f, indent=2, ensure_ascii=False)

    print(f"Saved {len(records)} records.")

if __name__ == "__main__":
    data = scrape_all()
    save(data)
    print(f"Done. Sample: {data[0] if data else '(none)'}")

    ⚖️ The Ethos — What This Project Demonstrates

    • Check permission first — robots.txt read before any request.
    • Identify yourself honestly — custom User-Agent with contact info.
    • Be gentle — random 1–2 second delays between pages.
    • Fail gracefully — retries with backoff, per-item try/except, no crash on any single error.
    • Save data cleanly — both human-readable (CSV) and machine-readable (JSON).
    Final principle: Every scraper you write is a guest on someone else's server. Act like a guest — be polite, be identifiable, be honest about why you're there. Scraping responsibly is a skill; scraping without conscience is a liability. The tools in this course give you the power to scrape; it's up to you to use them with judgment.
