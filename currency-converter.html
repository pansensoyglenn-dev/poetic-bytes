    01 — The Idea

    Why Build a Currency Converter?

    💱 Money Is a Value Type — Treat It Like One

    In every real application — banking, e-commerce, invoicing, payroll — money shows up. And in almost every beginner codebase, it shows up the wrong way: as a plain float. Floats lie (0.1 + 0.2 != 0.3), they carry no currency, and they let you accidentally add dollars to euros.

    A Money class fixes all of that. It stores an amount and a currency, refuses mismatched arithmetic, rounds correctly, and — through operator overloading — lets you write price + tax instead of price.add(tax).

    Then a CurrencyConverter sits on top: it holds exchange rates and turns Money(100, "USD") into Money(5600, "PHP"). Finally, polymorphic payment methods show how the same checkout() call handles cards, cash and digital wallets.

    7 programs with line-by-line walkthroughs 6 exercises with solutions Interactive live lab Free-form Python playground Progress tracker Full project walkthrough

    The Problem: Float Money

    Watch what plain floats do when you try to run a simple checkout.

    price = 19.99
tax = 1.60
total = price + tax
print(total)
print(total == 21.59)
print(0.1 + 0.2 == 0.3)
    Expected output
    21.590000000000003 False False

    Smell: The total is wrong at the 15th decimal place. Comparison against the "correct" answer fails. This is binary floating point, and money code cannot tolerate it.

    Goal: A class that stores integer cents (or Decimal), knows its currency, refuses mixed-currency addition, and renders as PHP 21.59.

    03 — Build It

    Seven Programs, Explained Line by Line

    Program 1 — A Money Value Object

    Start small: a class that stores amount and currency, prevents mixed arithmetic, and prints nicely. We use Decimal internally for exactness.

    from decimal import Decimal, ROUND_HALF_UP

class Money:
    def __init__(self, amount, currency="USD"):
        self.amount = Decimal(str(amount)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
        self.currency = currency.upper()

    def _check(self, other):
        if self.currency != other.currency:
            raise ValueError(f"Currency mismatch: {self.currency} vs {other.currency}")

    def __add__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        self._check(other)
        return Money(self.amount + other.amount, self.currency)

    def __sub__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        self._check(other)
        return Money(self.amount - other.amount, self.currency)

    def __eq__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        return (self.amount, self.currency) == (other.amount, other.currency)

    def __hash__(self):
        return hash((self.amount, self.currency))

    def __repr__(self):
        return f"Money({self.amount!s}, {self.currency!r})"

    def __str__(self):
        return f"{self.currency} {self.amount:,.2f}"

price = Money("19.99")
tax = Money("1.60")
print(price)
print(price + tax)
print(Money("0.10") + Money("0.20"))
print(price == Money("19.99"))

try:
    Money("1.00") + Money("1.00", "EUR")
except ValueError as err:
    print("ValueError:", err)
    Expected output
    USD 19.99 USD 21.59 USD 0.30 True ValueError: Currency mismatch: USD vs EUR

    🔍 Deep dive — why Decimal(str(amount))?

    The easiest bug in money code is the one you don't notice until the ledger is off by a cent. Let's see what the constructor is really doing.

    InputWrong way: Decimal(19.99)Right way: Decimal("19.99")
    19.9919.989999999999998436…19.99
    0.10.1000000000000000055511…0.1
    Why?Float is already wrong before Decimal sees it.str() captures the human representation.

    The rule: when a value represents money, it must travel as a string or integer all the way into the constructor, and only become a number inside __init__.

    📖 Line-by-line walkthrough

    1. from decimal import Decimal, ROUND_HALF_UP — imports the fixed-point type and the rounding mode. ROUND_HALF_UP means 2.5 becomes 3, which matches how money is normally rounded.
    2. class Money: — a plain class, no inheritance needed. A value object stands alone.
    3. def __init__(self, amount, currency="USD"): — the constructor takes any amount-like input and a currency code that defaults to USD.
    4. Decimal(str(amount)) — converts the input to a string first, then to a Decimal. This is the safety step that prevents float contamination.
    5. .quantize(Decimal("0.01"), rounding=ROUND_HALF_UP) — snaps the value to two decimal places using banker-safe rounding.
    6. self.currency = currency.upper() — normalizes currency codes so "usd" and "USD" are treated as the same.
    7. def _check(self, other) — a private helper. Raises ValueError if the two objects don't agree on currency. Note the leading underscore by convention.
    8. def __add__(self, other) — hooked to +. First rejects non-Money operands via NotImplemented. Then checks currencies. Then returns a new Money.
    9. def __sub__(self, other) — same shape for -. Note that the result can be negative; we don't forbid that here (a refund is a valid concept).
    10. def __eq__(self, other) — compares both amount and currency. Money("1.00") == Money("1.00", "EUR") correctly returns False.
    11. def __hash__(self) — without this, the object is unhashable once __eq__ is defined. It uses the same tuple so equal objects hash the same.
    12. def __repr__(self) — for developers. Shows the exact fields, useful in debugging.
    13. def __str__(self) — for users. Formats with thousands separators and two decimals.
    14. Money("0.10") + Money("0.20") — the classic float-fail test. Prints USD 0.30 — exactly right.
    15. The final try/except — attempts to add USD and EUR. Our _check raises ValueError with a clear message.

    ⚠️ Common mistakes

    Passing a float to Decimal directly. Decimal(0.1) stores the float error. Always pass a string.

    Mutating amount after creation. A value object should be immutable; money.amount = ... breaks the mental model. Use __add__ to create new ones.

    Forgetting __hash__. Defining __eq__ sets __hash__ to None. Money objects in a set will raise TypeError.

    Program 2 — Multiplication and Comparison

    Now make Money arithmetic usable: scaling, ordering, min/max, sorted. A real checkout needs all of these.

    from decimal import Decimal, ROUND_HALF_UP
from functools import total_ordering

@total_ordering
class Money:
    def __init__(self, amount, currency="USD"):
        self.amount = Decimal(str(amount)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
        self.currency = currency.upper()

    def _check(self, other):
        if self.currency != other.currency:
            raise ValueError(f"Currency mismatch: {self.currency} vs {other.currency}")

    def __add__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        self._check(other)
        return Money(self.amount + other.amount, self.currency)

    def __mul__(self, factor):
        if not isinstance(factor, (int, float, Decimal)):
            return NotImplemented
        return Money(self.amount * Decimal(str(factor)), self.currency)

    __rmul__ = __mul__

    def __eq__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        return (self.amount, self.currency) == (other.amount, other.currency)

    def __lt__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        self._check(other)
        return self.amount < other.amount

    def __hash__(self):
        return hash((self.amount, self.currency))

    def __repr__(self):
        return f"Money({self.amount!s}, {self.currency!r})"

    def __str__(self):
        return f"{self.currency} {self.amount:,.2f}"

price = Money("19.99")
print(price * 3)
print(3 * price)
print(min(Money("5"), Money("10")))
print(max(Money("5"), Money("10")))
print(sorted([Money("30"), Money("5"), Money("12.50")]))
print(Money("5") < Money("10"))
print(Money("5") <= Money("5"))

try:
    Money("1", "USD") < Money("1", "EUR")
except ValueError as err:
    print("ValueError:", err)
    Expected output
    USD 59.97 USD 59.97 USD 5.00 USD 10.00 [Money(5.00, 'USD'), Money(12.50, 'USD'), Money(30.00, 'USD')] True True ValueError: Currency mismatch: USD vs EUR

    🔍 Deep dive — how the operators resolve

    Follow each expression to its underlying method calls.

    You writePython triesResult
    price * 3price.__mul__(3)New Money("59.97").
    3 * price① int.__mul__(3, price) → NotImplemented
    ② price.__rmul__(3)    		The reflected method handles it — that's why __rmul__ = __mul__ works.
    min(a, b)repeated a < b → __lt__Smaller amount.
    sorted([...])Pairwise <, using __lt__Sorted ascending.
    a <= b__le__, derived by @total_ordering from __eq__ + __lt__Correct comparison.
    a < b (mixed currency)__lt__ calls _check which raises ValueErrorPrevents nonsense ordering.

    Ordering requires a currency: comparing USD 5 to EUR 5 is only meaningful after conversion. Our _check ensures you don't quietly get the wrong answer.

    📖 Line-by-line walkthrough

    1. from functools import total_ordering — a decorator from the standard library. You write __eq__ and one ordering method (__lt__); it fills in the other three comparisons.
    2. @total_ordering — must appear directly above the class definition. It rewrites the class to add missing comparison methods.
    3. def __mul__(self, factor) — accepts any number-like factor. Returns a new Money with self.amount * factor.
    4. Decimal(str(factor)) — converts the factor safely to Decimal. If factor is a float, we still capture its human form.
    5. __rmul__ = __mul__ — the reflected form. It is the same function because multiplication is commutative. When Python tries 3 * price, int.__mul__ fails and the reflected method is called.
    6. def __lt__(self, other) — the one ordering primitive @total_ordering needs. It rejects non-Money and checks currencies.
    7. self.amount < other.amount — Decimal supports comparison, so this just works.
    8. The demonstration lines — price * 3 and 3 * price both produce USD 59.97. min and max use __lt__. sorted arranges the list by amount.
    9. Money("5") < Money("10") — the direct call. True.
    10. Money("5") <= Money("5") — __le__ was synthesized by @total_ordering. True.
    11. The final test — mixed-currency comparison raises ValueError, not TypeError — because our code raised it intentionally.

    ⚠️ Common mistakes

    Forgetting @total_ordering. Without it, only the operators you define work. Money("5") >= Money("3") would raise TypeError.

    Not defining __rmul__. Then 3 * price fails — even though price * 3 works.

    Multiplying two Moneys. Money("5") * Money("3") silently returns USD 15.00. That doesn't make financial sense. Add a check that rejects isinstance(factor, Money).

    Program 3 — The Currency Converter

    Now the "converter" part. Rates are held in one place. A single method does the conversion — but returns a new Money object; it never mutates the original.

    from decimal import Decimal, ROUND_HALF_UP

class Money:
    def __init__(self, amount, currency="USD"):
        self.amount = Decimal(str(amount)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
        self.currency = currency.upper()

    def __repr__(self):
        return f"Money({self.amount!s}, {self.currency!r})"

    def __str__(self):
        return f"{self.currency} {self.amount:,.2f}"

class CurrencyConverter:
    def __init__(self, rates=None):
        self.rates = rates or {
            ("USD", "PHP"): Decimal("56.00"),
            ("PHP", "USD"): Decimal("1") / Decimal("56.00"),
            ("USD", "EUR"): Decimal("0.92"),
            ("EUR", "USD"): Decimal("1") / Decimal("0.92"),
            ("USD", "JPY"): Decimal("149.50"),
            ("JPY", "USD"): Decimal("1") / Decimal("149.50"),
        }

    def rate(self, source, target):
        source, target = source.upper(), target.upper()
        if source == target:
            return Decimal("1")
        key = (source, target)
        if key not in self.rates:
            raise KeyError(f"No rate for {source} → {target}")
        return self.rates[key]

    def convert(self, money, target):
        rate = self.rate(money.currency, target)
        return Money(money.amount * rate, target)

converter = CurrencyConverter()
salary = Money("5000", "USD")
print(salary)
print(converter.convert(salary, "PHP"))
print(converter.convert(salary, "EUR"))
print(converter.convert(salary, "JPY"))
print(converter.convert(salary, "USD"))

try:
    converter.convert(salary, "AUD")
except KeyError as err:
    print("KeyError:", err)

class Product:
    def __init__(self, name, price):
        self.name = name
        self.price = price

products = [
    Product("Coffee", Money("4.50", "USD")),
    Product("Lunch", Money("12.00", "USD")),
]
for p in products:
    print(f"{p.name:<8} {p.price}  →  {converter.convert(p.price, 'PHP')}")
    Expected output
    USD 5,000.00 PHP 280,000.00 EUR 4,600.00 JPY 747,500.00 USD 5,000.00 KeyError: 'No rate for USD → AUD' Coffee USD 4.50 → PHP 252.00 Lunch USD 12.00 → PHP 672.00

    🔍 Deep dive — why return a new object?

    You could design convert to mutate. Don't. Here is why immutability pays off.

    DesignMutatingReturning new
    Called twiceConverts twice — 5000 → 280000 → 15,680,000 (bug!)Same result each time.
    Original salarySilently changedPreserved.
    Thread-safe?NoYes.
    Hashable?Danger — hash can change mid-dict.Safe.

    The rule: any method returning money must return a new Money. If you feel tempted to mutate, you need to stop and think about why.

    📖 Line-by-line walkthrough

    1. class CurrencyConverter: — a pure data holder. No inheritance needed. The design is a table plus a lookup.
    2. def __init__(self, rates=None) — accepts an optional rates dict. If none given, uses defaults. This makes the class testable: pass fake rates in tests.
    3. rates or { ... } — Python's idiom for defaults. If rates is falsy (None or empty), use the literal.
    4. ("USD", "PHP"): Decimal("56.00") — a tuple key. The pair ("USD", "PHP") is one lookup key.
    5. Decimal("1") / Decimal("56.00") — the reverse rate is computed once at init. This is more accurate than typing 0.017857.
    6. def rate(self, source, target) — public helper. Normalizes both currency codes, handles the trivial same-currency case, and raises KeyError for unknown pairs.
    7. if source == target: return Decimal("1") — you don't need a table entry for a no-op conversion.
    8. if key not in self.rates: raise KeyError(...) — explicit failure. The error message tells you exactly what's missing.
    9. def convert(self, money, target) — one line of logic: look up the rate, multiply, wrap in Money. The Money constructor rounds and normalizes the currency.
    10. return Money(money.amount * rate, target) — the new object. Original money is never touched.
    11. The demonstration lines — one salary, four targets. Each convert call is independent.
    12. Money("5000", "USD") — even though the amount is a whole number, it still becomes USD 5,000.00 because we round to two decimals uniformly.
    13. Product class — very simple, but it demonstrates the real pattern: the converter slots right into a shopping cart.
    14. The final loop — f"{p.name:<8}" left-aligns the name in 8 characters. The → is just a unicode arrow. Both product prices convert via the same method.

    ⚠️ Common mistakes

    Storing rates as floats. Use Decimal("56.00"), not 56.0. Otherwise every conversion reintroduces float error.

    Storing only one direction. You can derive the reverse, but if precision matters, store both as Decimal values.

    Forgetting to normalize currency codes. If Money stores "USD" but the converter asks for "usd", lookup fails. We call .upper() on both sides.

    Program 4 — Mixed-Currency Arithmetic (Fixed)

    So far, mixed-currency addition raises an error. In real life, if you spend 100 USD and 5000 PHP, you want a total — probably in your home currency. The code below fixes the previous KeyError by introducing a base-currency routing method in the Rates class.

    from decimal import Decimal, ROUND_HALF_UP

class Money:
    def __init__(self, amount, currency="USD"):
        self.amount = Decimal(str(amount)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
        self.currency = currency.upper()

    def __add__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        if self.currency != other.currency:
            raise ValueError(f"Cannot add {self.currency} and {other.currency}")
        return Money(self.amount + other.amount, self.currency)

    def __repr__(self):
        return f"Money({self.amount!s}, {self.currency!r})"

    def __str__(self):
        return f"{self.currency} {self.amount:,.2f}"

class Wallet:
    def __init__(self, converter):
        self.converter = converter
        self.balances = {}

    def add(self, money):
        self.balances[money.currency] = self.balances.get(money.currency, Money("0", money.currency)) + money

    def total(self, target):
        result = Money("0", target)
        for currency, amount in self.balances.items():
            result = result + self.converter.convert(amount, target)
        return result

class Rates:
    def __init__(self):
        self.table = {
            "PHP": Decimal("56.00"),
            "EUR": Decimal("0.92"),
            "GBP": Decimal("0.79"),
        }

    def convert(self, money, target):
        if money.currency == target:
            return money
            
        target_upper = target.upper()
        source_upper = money.currency.upper()
        
        if source_upper == "USD":
            source_to_usd = Decimal("1")
        elif source_upper in self.table:
            source_to_usd = Decimal("1") / self.table[source_upper]
        else:
            raise KeyError(f"Unsupported currency: {source_upper}")

        if target_upper == "USD":
            usd_to_target = Decimal("1")
        elif target_upper in self.table:
            usd_to_target = self.table[target_upper]
        else:
            raise KeyError(f"Unsupported currency: {target_upper}")

        final_rate = source_to_usd * usd_to_target
        return Money(money.amount * final_rate, target)

wallet = Wallet(Rates())
wallet.add(Money("100.00", "USD"))
wallet.add(Money("5600.00", "PHP"))
wallet.add(Money("50.00", "EUR"))

print("Balances:", wallet.balances)
print("In USD:", wallet.total("USD"))
print("In PHP:", wallet.total("PHP"))
print("In EUR:", wallet.total("EUR"))

try:
    Money("1.00", "USD") + Money("1.00", "PHP")
except ValueError as err:
    print("ValueError:", err)
    Expected output
    Balances: {'USD': Money(100.00, 'USD'), 'PHP': Money(5600.00, 'PHP'), 'EUR': Money(50.00, 'EUR')} In USD: USD 246.00 In PHP: PHP 13,776.00 In EUR: EUR 226.32 ValueError: Cannot add USD and PHP

    🔍 Deep dive — the two legitimate designs

    QuestionRefuse mixed addAuto-convert
    Predictable?Yes — nothing hidden.No — the rate table becomes a hidden dependency.
    Silent wrong answer?Impossible — raises.Possible if rate is stale.
    Great forPayment math, accountingDisplay, "show me everything in my home currency"
    WhereInside MoneyInside a Wallet / portfolio object

    The design we chose: Money refuses mixed arithmetic. The Wallet object — which knows the converter — does the conversion explicitly. Each class carries only what it can safely handle.

    📖 Line-by-line walkthrough

    1. def __add__ raising on mixed currencies — the class-level policy. Same design as Program 1.
    2. class Wallet — the composer. It holds multiple currency amounts and knows a converter. This is aggregation (has-a), not inheritance.
    3. self.balances = {} — a dictionary keyed by currency code. Amounts are Money objects, not floats.
    4. self.balances.get(money.currency, Money("0", money.currency)) — a neat idiom. If the key is present, returns its value. If not, returns a zero Money in that currency.
    5. + money — the (same-currency) Money add. This triggers __add__, which passes because currencies match.
    6. def total(self, target) — starts with a zero Money in the target currency. Then adds each converted balance.
    7. result = result + self.converter.convert(amount, target) — the convert first produces a Money in the target, then + adds it — same currency now, so it succeeds.
    8. class Rates — a simpler converter used only by the wallet. It keeps the demo self-contained.
    9. if money.currency == target: return money — short-circuit. No lookup needed for same-currency.
    10. source_to_usd and usd_to_target — this is the fix. Instead of looking for a direct ("EUR", "PHP") key, we convert EUR to USD first, then USD to PHP. This means we only need to store rates relative to USD.
    11. wallet.add(Money("100", "USD")) — adds $100. Then wallet.add(Money("5600", "PHP")) adds 5600 PHP. Then 50 EUR.
    12. wallet.total("USD") — converts each balance: $100 + ($5600/56=) $100 + (50*0.92=) $46 = $246. The math now works perfectly.

    ⚠️ Common mistakes

    Auto-converting inside __add__. That couples Money to a global rates table. Now Money cannot be used in a context where the rates might be stale or missing.

    Using dict.setdefault with a mutable default. defaultdict(Money) would fail because Money() requires arguments.

    Storing each currency in a separate attribute. wallet.usd, wallet.php, wallet.eur doesn't scale. A dict is the right structure.

    Program 5 — Full Checkout Flow

    from decimal import Decimal, ROUND_HALF_UP
from functools import total_ordering

@total_ordering
class Money:
    def __init__(self, amount, currency="USD"):
        self.amount = Decimal(str(amount)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
        self.currency = currency.upper()

    def _check(self, other):
        if self.currency != other.currency:
            raise ValueError(f"Cannot add {self.currency} and {other.currency}")

    def __add__(self, other):
        if not isinstance(other, Money): return NotImplemented
        self._check(other)
        return Money(self.amount + other.amount, self.currency)

    def __sub__(self, other):
        if not isinstance(other, Money): return NotImplemented
        self._check(other)
        return Money(self.amount - other.amount, self.currency)

    def __mul__(self, factor):
        if not isinstance(factor, (int, Decimal)): return NotImplemented
        return Money(self.amount * Decimal(str(factor)), self.currency)

    __rmul__ = __mul__

    def __eq__(self, other):
        if not isinstance(other, Money): return NotImplemented
        return (self.amount, self.currency) == (other.amount, other.currency)

    def __lt__(self, other):
        if not isinstance(other, Money): return NotImplemented
        self._check(other)
        return self.amount < other.amount

    def __hash__(self):
        return hash((self.amount, self.currency))

    def __repr__(self):
        return f"Money({self.amount!s}, {self.currency!r})"

    def __str__(self):
        return f"{self.currency} {self.amount:,.2f}"

class LineItem:

        self.unit_price = unit_price
        self.quantity = quantity

class Cart:
    def __init__(self, tax_rate=Decimal("0.12")):
        self.items = []
        self.tax_rate = tax_rate
        self.discount = None

    def add(self, item):
        self.items.append(item)
        return self

    def apply_discount(self, amount):
        self.discount = amount
        return self

        for item in self.items:
            total = total + item.subtotal()

        return self.subtotal() * self.tax_rate

    def total(self):

        return base

    Program 6 — Polymorphic Payment Methods

    The last piece: the same checkout() call handles cards, cash, and wallets. Each method calculates its fee differently. New methods slot in without touching the caller.

    from decimal import Decimal, ROUND_HALF_UP

class Money:
    def __init__(self, amount, currency="USD"):
        self.amount = Decimal(str(amount)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
        self.currency = currency.upper()

    def __add__(self, other):
        if not isinstance(other, Money): return NotImplemented
        if self.currency != other.currency:

        return Money(self.amount + other.amount, self.currency)

    def __mul__(self, factor):
        if not isinstance(factor, (int, Decimal)): return NotImplemented
        return Money(self.amount * Decimal(str(factor)), self.currency)

    def __str__(self):

class PaymentMethod:
    def fee(self, amount):
        raise NotImplementedError

    def checkout(self, amount):
        fee = self.fee(amount)
        total = amount + fee
        return f"{type(self).__name__:<12} total {total}  (fee {fee})"

class CardPayment(PaymentMethod):
    def fee(self, amount):
        return amount * Decimal("0.029") + Money("15.00", amount.currency)

class CashPayment(PaymentMethod):
    def fee(self, amount):
        return Money("0", amount.currency)

class WalletPayment(PaymentMethod):
    def fee(self, amount):
        return amount * Decimal("0.02")

class CryptoPayment(PaymentMethod):
    def fee(self, amount):
        return amount * Decimal("0.01")

    🔍 Deep dive — why checkout is a Template Method

    The base class defines the steps of checkout. Subclasses define only the fee. Python dispatches self.fee(amount) on the real subclass.

    StepWhat runsWhere
    1. Compute feeself.fee(amount)Overridden per subclass
    2. Add feeamount + feeShared, in base class
    3. Format receiptf-stringShared, in base class

    Zero duplicate code. Every subclass inherits the checkout algorithm. They differ only in the one rule that actually differs. This is polymorphism at its most useful.

    Want a new method? Write class BankTransfer(PaymentMethod) with its own fee. The loop that iterates methods doesn't need to know it exists.

    📖 Line-by-line walkthrough

    1. Money class — a minimal version for this demo. Only what we need: +, *, str.
    2. class PaymentMethod — the base. Provides a full checkout() and a placeholder fee().
    3. def fee(self, amount): raise NotImplementedError — explicit failure. Calling it signals a subclass bug.
    4. def checkout(self, amount) — the Template Method. Three steps: fee, add, format. self.fee(amount) will dispatch to the subclass.
    5. type(self).__name__ — gets the class name as a string. So CardPayment, CashPayment, etc. work without hard-coding.
    6. class CardPayment(PaymentMethod) — inherits from the base. Only overrides fee.
    7. amount * Decimal("0.029") + Money("15.00", amount.currency) — a percentage plus a fixed amount. Note that Money(...) needs the same currency as amount.
    8. CashPayment.fee — a zero Money. Uses amount.currency so it works with any input.
    9. WalletPayment.fee and CryptoPayment.fee — pure percentages. Small changes, big variety.
    10. methods = [...] — the polymorphic list. Each object knows its own fee.
    11. The for loop — one line, four behaviors. Prints a full receipt per method.
    12. PaymentMethod().checkout(amount) — instantiating the base directly. self.fee(amount) hits the base method and raises NotImplementedError.

    ⚠️ Common mistakes

    Forgetting to override fee. Then checkout raises NotImplementedError. Use abc.ABC + @abstractmethod to catch this at creation time.

    Hardcoding currency inside a subclass. Money("15.00", "USD") would break if the cart is in PHP. Use amount.currency instead.

    Returning None from fee in one method. Then amount + fee raises TypeError. Always return a Money.

    Program 7 — Live Interactive Converter (Full App)

    from decimal import Decimal, ROUND_HALF_UP
import urllib.request
import json
import csv
from datetime import datetime

class Money:
    def __init__(self, amount, currency="USD"):

class InteractiveConverter:
    def __init__(self):
        # Default fallback rates in case of offline usage
        self.rates = {
            "USD": Decimal("1.00"),
            "PHP": Decimal("56.00"),
            "EUR": Decimal("0.92"),
            "JPY": Decimal("149.50"),
            "GBP": Decimal("0.79"),
            "AUD": Decimal("1.52"),
            "CAD": Decimal("1.36")
        }
        self.fetch_live_rates()

    def fetch_live_rates(self):
        """Fetches live exchange rates using a free open API endpoint."""
        url = "https://open.er-api.com/v6/latest/USD"
        try:
            req = urllib.request.Request(url, headers={'User-Agent': 'Mozilla/5.0'})
            with urllib.request.urlopen(req, timeout=3) as response:
                data = json.loads(response.read().decode())
                if data.get("result") == "success":
                    self.rates = {code: Decimal(str(rate)) for code, rate in data["rates"].items()}
                    print("[Info] Successfully fetched live exchange rates!")
        except Exception as e:
            print("[Warning] Could not fetch live rates. Using offline fallback rates.")

    def get_rate(self, source, target):
        source = source.upper()
        target = target.upper()
        if source not in self.rates:
            raise ValueError(f"Unsupported source currency: {source}")
        if target not in self.rates:
            raise ValueError(f"Unsupported target currency: {target}")
            
        usd_amount = Decimal("1") / self.rates[source]
        return usd_amount * self.rates[target]

    def convert(self, money, target_currency):
        rate = self.get_rate(money.currency, target_currency)
        return Money(money.amount * rate, target_currency)

class HistoryManager:
    """Manages reading and logging conversion history to both CSV and TXT files."""
    def __init__(self, csv_filename="conversion_history.csv", txt_filename="conversion_history.txt"):
        self.csv_filename = csv_filename
        self.txt_filename = txt_filename
        self._init_csv()

    def _init_csv(self):
        try:
            with open(self.csv_filename, mode='x', newline='', encoding='utf-8') as f:
                writer = csv.writer(f)
                writer.writerow(["Timestamp", "Source Currency", "Source Amount", "Target Currency", "Target Amount", "Exchange Rate"])
        except FileExistsError:
            pass

    def log_conversion(self, money_from, money_to, rate):
        timestamp = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
        
        # Append to CSV
        with open(self.csv_filename, mode='a', newline='', encoding='utf-8') as f:
            writer = csv.writer(f)
            writer.writerow([timestamp, money_from.currency, str(money_from.amount), money_to.currency, str(money_to.amount), f"{rate:.6f}"])
            
        # Append to formatted TXT log
        with open(self.txt_filename, mode='a', encoding='utf-8') as f:
            f.write(f"[{timestamp}] {money_from} -> {money_to} (Rate: 1 {money_from.currency} = {rate:.4f} {money_to.currency})\n")

    def show_history(self):
        try:
            with open(self.txt_filename, mode='r', encoding='utf-8') as f:
                logs = f.readlines()
                if not logs:
                    print("\n--- No Conversion History Found ---")
                    return
                print("\n=====================================")
                print("       CONVERSION HISTORY LOG        ")
                print("=====================================")
                for log in logs[-10:]:  # Show last 10 conversions
                    print(log.strip())
                print("=====================================")
        except FileNotFoundError:
            print("\n--- No Conversion History Found ---")

    def __str__(self):
        return f"{self.currency} {self.amount:,.2f}"

def split(amount, people):
    if people <= 0:
        raise ValueError("people must be positive")
    total_cents = int(amount.amount * 100)
    base = total_cents // people
    remainder = total_cents % people
    shares = []
    for i in range(people):
        cents = base + (1 if i < remainder else 0)
        shares.append(Money(Decimal(cents) / 100, amount.currency))
    return shares

shares = split(Money("100.00"), 3)
for s in shares:
    print(s)

total = Money("0")
for s in shares:
    total = total + s
print("Sum:", total)
    Expected output
    USD 33.34 USD 33.33 USD 33.33 Sum: USD 100.00

    100.00 / 3 = 33.333..., so two people pay 33.33 and one pays 33.34. The sum matches exactly — no missing cent, no duplicating cent. This is how real payment apps split bills.

    Exercise 5 — A Savings Goal Tracker

    Medium

    Task: write a SavingsGoal class holding a target and a current amount (both Money). Add a contribute(amount) method. Add a percent() returning the fraction saved. Print progress.

    Hint: percent = (current / target) * 100. You'll need __truediv__ or use current.amount / target.amount.

    Show solution & explanation 
    from decimal import Decimal, ROUND_HALF_UP

class Money:
    def __init__(self, amount, currency="USD"):
        self.amount = Decimal(str(amount)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
        self.currency = currency.upper()

    def __add__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        if self.currency != other.currency:
            raise ValueError("Currency mismatch")
        return Money(self.amount + other.amount, self.currency)

    def __str__(self):
        return f"{self.currency} {self.amount:,.2f}"

class SavingsGoal:
    def __init__(self, target):
        self.target = target
        self.current = Money("0", target.currency)

    def contribute(self, amount):
        self.current = self.current + amount
        return self

    def percent(self):
        if self.target.amount == 0:
            return Decimal("100")
        return (self.current.amount / self.target.amount * 100).quantize(Decimal("0.01"))

goal = SavingsGoal(Money("500.00"))
goal.contribute(Money("150.00")).contribute(Money("75.50"))
print(f"Saved: {goal.current}")
print(f"Target: {goal.target}")
print(f"Progress: {goal.percent()}%")
    Expected output
    Saved: USD 225.50 Target: USD 500.00 Progress: 45.10%

    The contribute method returns self so calls can be chained. The percent uses Decimal division for exactness. 225.50/500 × 100 = 45.10%.

    Hint: watch out for float-to-Decimal, missing __eq__, missing __hash__, and forgotten rounding.

    Show solution & explanation 
    from decimal import Decimal, ROUND_HALF_UP

class Money:
    def __init__(self, amount, currency="USD"):
        self.amount = Decimal(str(amount)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
        self.currency = currency.upper()

    def __add__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        if self.currency != other.currency:
            raise ValueError("Currency mismatch")
        return Money(self.amount + other.amount, self.currency)

    def __eq__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        return (self.amount, self.currency) == (other.amount, other.currency)

    def __hash__(self):
        return hash((self.amount, self.currency))

    def __str__(self):
        return f"{self.currency} {self.amount:.2f}"

a = Money(10.99)
b = Money(5.01)
c = a + b
print(c)
print(c == Money(16.00))
print(len({a, a}))
    Expected output
    USD 16.00 True 1

    Bug 1: Decimal(amount) on a float captured float error. Bug 2: No __eq__ meant c == Money(16.00) was False by default identity. Bug 3: No __hash__ made the object unhashable. Bug 4: No rounding meant cents could drift at the 15th decimal.

    07 — Do's & Don'ts

    Best Practices for Money Code

    Habits That Keep Money Code Safe

    ✓ DO: Use Decimal internally. Never store money as a float. If you accept a float, convert via str().

    ✓ DO: Round consistently. Every amount gets the same rounding mode and precision. Pick ROUND_HALF_UP or your country's standard and never deviate.

    ✓ DO: Refuse mixed-currency arithmetic. Use ValueError with a clear message. Force the caller to convert explicitly.

    ✓ DO: Return new objects from methods. Treat Money as immutable. Value objects should never mutate.

    ✓ DO: Define __eq__ and __hash__ together. Otherwise equal money objects in a set behave strangely.

    ✓ DO: Store currency codes as uppercase. "USD", not "usd". Normalize in __init__.

    ✗ DON'T: Store tax rates as floats. Use Decimal("0.12"). Otherwise every calculation drifts.

    ✗ DON'T: Round inside operators. Round once, at the end of a calculation, or with each Money creation — not at multiple intermediate points.

    ✗ DON'T: Ignore currency in comparison. USD 5 == EUR 5 should be False — the currencies differ, even if the numeric amounts match.

    ✗ DON'T: Trust float conversion. If you have to store a float anywhere, immediately convert to string then Decimal.

    Key Takeaways

    • Money must be Decimal, not float. Floats lie. Always str() before Decimal().
    • Value objects are immutable. Operators return new objects, never mutate.
    • Refuse mixed-currency arithmetic. Convert explicitly — don't hide the rate inside __add__.
    • Define __eq__ and __hash__ together. One without the other causes bugs.
    • Use @total_ordering to derive comparisons from __eq__ + __lt__.
    • Compose, don't inherit. Wallet has Money objects and has a converter. It isn't a subclass of either.
    • Template Method for checkout. Base class owns the algorithm; subclasses only change the variable part.
    • Return NotImplemented from operators for unsupported operand types.
